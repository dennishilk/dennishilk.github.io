# Snakkie: fixed visual character reference

User decision, 2026-10-30: **This exact Snakkie is the visual reference.** Future
expressions must depict the same character, not a newly invented penguin.

Current character canon, corrected by the user on 2026-10-30: **Snakkie is
Nebby's cousin.** Preserve that family relationship in DE/EN copy and AI persona.
The existing artwork stays canonical. The old working slogan “Nebby becomes
Snakkie” is historical provenance and must not return as the public story.

Canonical visual reference: [`snakkie-captain-source.png`](snakkie-captain-source.png)
(1254×1254, transparent RGBA). SHA-256:
`a0b7a6c4c18478be09ee1b17a903621b09a6dd57317ce7d9469ed86a1cf93b02`.

The optimized `snakkie-captain-768.webp` and `snakkie-captain-480.webp` show the
same approved character; `snakkie-avatar.webp` is its small web derivative.

For future normal, winking, thoughtful, laughing or animated variants:

- Open and use the canonical **Snakkie image as the edit/reference input**.
  A text description alone is not sufficient. Original astronaut Nebby is
  provenance, not a substitute for Snakkie's established sailor appearance.
- Preserve the rounded navy-blue body, exact cream face pattern, large black
  eyes, eyebrows, orange beak and feet, head/body proportions and polished
  illustration style.
- Preserve the blue/white horizontally striped shirt, white captain's hat,
  black visor and gold anchor. Keep recognizable garment shapes and palette.
- Change only the expression or pose requested. Do not redesign the face,
  species, anatomy, clothing or visual style as part of an expression change.
- Compare every result against the canonical image before integrating it.
  If identity drifts, correct it rather than treating a different penguin as
  another Snakkie expression. Do not promise pixel-identical generated edits.
- Keep original Nebby and the canonical Snakkie source intact. Save new
  variants separately with descriptive filenames; preserve transparency.
- A new canonical design requires an explicit user decision. Do not silently
  replace the reference when creating a variant.
