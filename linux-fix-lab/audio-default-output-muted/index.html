Sound goes to the wrong or muted output

Use PipeWire default-device and volume evidence to distinguish a muted sink or retained application route from a missing sound device or driver failure.

Symptoms & scope

  • Applications appear to play but the expected speakers stay silent.
  • Audio reaches an unused monitor or a previously connected headset.

Relevant environment

PipeWire desktops managed by WirePlumber, with multiple speakers, HDMI outputs or USB headsets.

Possible causes

These are possible explanations, not a confirmed diagnosis. Several independent faults can coexist.

  • The default sink may be muted or a different device may have been selected and remembered.
  • An application can retain its own target or volume independently of the current default sink.

Diagnose safely

Run one command at a time in the relevant session. Read the explanation first. Uppercase placeholders need your own values; tools and privileges vary by distribution. These commands are displayed here and never executed by the website.

Check 1

Read sinks, streams and the default marker as the logged-in desktop user; no route is changed.

wpctl status

Interpret the result: A visible expected sink confirms graph exposure. A different default or application target is a routing lead; a missing sink needs device/profile investigation.

Check 2

Read the current default output’s volume and mute state without changing it.

wpctl get-volume @DEFAULT_AUDIO_SINK@

Interpret the result: [MUTED] explains silence at that sink; a normal level does not rule out application mute, hardware mixer mute or an incorrect route.

Evidence-guided next steps

Select and unmute the verified output

If wpctl shows the intended output and the wrong default, select that sink in the desktop audio panel or with wpctl set-default using its current ID. If muted, unmute that sink and start at a modest volume.

Precautions: IDs change across restarts. Avoid raising every output to 100%, especially headphones or an amplifier with its own volume control.

Recovery / rollback: Record the original sink and volume first; select them again if the new choice is unsuitable.

Correct the application’s retained route

If only one running application remains silent after the default is correct, inspect its playback stream in the desktop mixer, route that stream to the verified sink and review its own mute/volume controls. Restart only the application if its backend does not retarget live.

Precautions: Save work before restarting the app. Per-stream routing differs from changing the system default and may be remembered by policy.

Recovery / rollback: Restore that stream’s previous target and application volume if needed; no global audio reset is required.
