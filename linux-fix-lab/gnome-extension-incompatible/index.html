A GNOME Shell extension breaks after a Shell update

GNOME Shell API changes can make an extension incompatible. Compare supported Shell versions and disable the affected extension in isolation.

Symptoms & scope

  • An extension becomes disabled or reports an error after an upgrade.
  • The issue disappears with the affected extension disabled.

Relevant environment

GNOME Shell with user or system extensions; command names and supported extension releases depend on the installed Shell version.

Possible causes

These are possible explanations, not a confirmed diagnosis. Several independent faults can coexist.

  • Extension metadata may not declare compatibility with the installed Shell.
  • A JavaScript API or import used by the extension may have changed.

Diagnose safely

Run one command at a time in the relevant session. Read the explanation first. Uppercase placeholders need your own values; tools and privileges vary by distribution. These commands are displayed here and never executed by the website.

Check 1

Reads the installed Shell executable’s version without starting a new desktop session.

gnome-shell --version

Interpret the result: Compare this release with the extension’s supported shell-version list; the running session can still use an older binary until relogin.

Check 2

Replace EXTENSION_UUID with the exact extension identifier, including any @ suffix; run as the desktop account.

gnome-extensions info EXTENSION_UUID

Interpret the result: Read its path, state and version. A missing UUID or bus error differs from a known extension in an incompatible/error state.

Evidence-guided next steps

Disable the one implicated extension

If the extension is implicated, use gnome-extensions disable EXTENSION_UUID or the Extensions app to disable only it. Save the previous state, then check the same desktop action; relogin if the installed Shell version and running session differ.

Precautions: Do not bypass extension-version validation or reset all GNOME settings. System-enforced extensions may require administrator policy changes.

Recovery / rollback: Reenable that UUID with gnome-extensions enable EXTENSION_UUID once a compatible version is available; retain the old disabled state if it was already disabled.

Install the extension release supporting this Shell

If the maintainer offers a compatible release, back up the user extension and its relevant settings, then update through the official Extensions service or the distribution’s package route. For a system extension, use its owning package rather than replacing files manually.

Precautions: Adding the new Shell version to metadata cannot repair changed APIs. Keep the extension disabled while compatibility remains uncertain.

Recovery / rollback: Restore the saved user extension/settings or supported package version, keeping it disabled if that version cannot run on the current Shell.
