Kernel module was built for a different kernel

A module’s version magic must fit the running kernel build; compare installed module metadata before rebuilding or selecting a boot entry.

Symptoms & scope

  • A driver fails to load with invalid module format.
  • Kernel log compares version magic with should be.

Relevant environment

Externally built or incorrectly packaged kernel modules after a kernel upgrade, custom build or copied module installation.

Recognizable messages (synthetic examples)
example_module: version magic '6.10.0 SMP preempt mod_unload' should be '6.11.0 SMP preempt mod_unload'

Rebuild or select the matching supported kernel/module pair; bypassing the validation does not establish compatibility.

Possible causes

These are possible explanations, not a confirmed diagnosis. Several independent faults can coexist.

  • The module may target another kernel release or configuration.
  • A stale initramfs or incorrectly installed custom module can select an old build; matching release text alone may still miss configuration differences.

Diagnose safely

Run one command at a time in the relevant session. Read the explanation first. Uppercase placeholders need your own values; tools and privileges vary by distribution. These commands are displayed here and never executed by the website.

Check 1

Read the running kernel release, rather than the newest installed package version.

uname -r

Interpret the result: Use this exact release when checking headers and module installation directories. Installing a new kernel does not switch the running kernel.

Check 2

Replace example_module with the failed module name. This reads the installed module metadata and does not load it.

modinfo -F vermagic example_module

Interpret the result: Compare release and build flags with the kernel’s rejection text. A match here may mean a different stale copy was loaded from the initramfs.

Evidence-guided next steps

Rebuild for the selected supported kernel

If metadata targets another kernel, install its exact supported headers/development package and rebuild the external module through the distribution’s DKMS or module-package workflow. Check build completion before reboot.

Precautions: Do not use --force-vermagic or force-load incompatible modules; bypassing the check can corrupt kernel memory.

Recovery / rollback: Boot the prior supported kernel and its original module package if rebuilding cannot produce a compatible module.

Replace the stale early module copy

If the disk module is correct but the error persists in early boot, rebuild the selected kernel’s initramfs with the packaged module and verify the boot entry references it. Avoid manually copying .ko files between release directories.

Precautions: Verify /boot or the ESP is mounted correctly and keep an older boot image. Signed-module enforcement can independently reject the rebuilt module.

Recovery / rollback: Restore the previous boot image or generation and corresponding module package if the regenerated entry fails.
