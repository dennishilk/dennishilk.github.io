01

Proton & Wine Doctor / Crash Investigator

A startup error, a frozen display and a system hard-lock need different evidence. Choose a symptom and answer the next question; the flow explains what each observation does and does not show.

Wine, Proton, DXVK and VKD3D-Proton: which layer is failing?
Wine
Implements Windows APIs. A prefix holds the application’s registry, files and configuration; changing or deleting it can remove settings and saves.
Proton
Steam’s game runtime combines Wine with graphics translation and integration patches. Experimental and community GE builds are different releases, not guaranteed fixes. Record the exact selected build before a controlled comparison.
DXVK
Translates supported Direct3D 8–11 paths to Vulkan. Device creation depends on the installed DXVK version, its required Vulkan features and the matching process architecture.
VKD3D-Proton
Translates Direct3D 12 to Vulkan. A working DXVK game does not establish the device features required by a different D3D12 game.

Launcher authentication, required runtime components and publisher-enabled anti-cheat support are separate startup constraints. Check the first failure and the game’s own support statements before treating a graphics warning as the cause.

Vulkan & Graphics Stack Inspector

Hardware identification, the bound kernel driver, Vulkan device enumeration and successful game rendering are four different observations. A 64-bit host Vulkan report also does not prove that a 32-bit game runtime can load its driver.

RADV and Intel ANV are Mesa Vulkan drivers; AMDVLK and NVIDIA use different driver paths. Check the selected ICD and runtime before forcing a driver. Wayland, X11 and Gamescope add presentation context, not an automatic explanation for a crash.

Paste evidence you already collected. This inspector reads text; it cannot access your GPU. Limit: 128 Ki characters. Nothing is executed or uploaded.

Start with a read-only graphics check

Read the PCI identity and “Kernel driver in use” separately. The “Kernel modules” field lists candidates. Then inspect Vulkan in the process architecture and container used by the game.

Read-only observation

lspci -nnk

Requirements: Requires pciutils. PCI enumeration is read-only; optional detail may require additional permission.

Keep the GPU PCI ID and “Kernel driver in use” together. “Kernel modules” lists candidates and does not establish binding.

04

Steam Launch Options Builder

Build a temporary diagnostic launch string from reviewed options. Choose the application API and runtime first. An option is a controlled test with requirements and side effects; it is not a general performance recommendation.

GPU selection requires a matching hybrid graphics setup. Restore “Keep the current default” to remove the selection variables. Wine and native choices explain their scope; the final %command% placeholder belongs to Steam.

Diagnostic options

PROTON_LOG=1 records one Proton launch for executable, runtime and graphics evidence.

Requirements, side effects and removal

Requires: A Windows game actually launched with Proton, including Experimental or a community Proton build that supports this option. Plain Wine and native Linux games do not use it.

Side effects: Writes steam-APPID.log to the configured Proton log directory, normally your home directory. Logging can affect timing; the file can contain private paths and account details.

Remove: Remove PROTON_LOG=1 from this game’s launch options and restart it. Review and delete the local log separately when no longer needed.

MANGOHUD=1 enables the installed Vulkan layer to observe frame times and workload. It changes no performance policy.

Requirements, side effects and removal

Requires: MangoHud must be installed for the application’s architecture and visible inside its Steam/Flatpak runtime. This environment-variable form is Vulkan only. OpenGL uses the mangohud wrapper; gamescope uses its supported mangoapp integration.

Side effects: An injected overlay can add overhead or conflict with other layers. Confirm that the game permits overlays; absence of an overlay does not prove Vulkan is broken.

Remove: Remove MANGOHUD=1 and restart the game. Keep an unchanged reference launch for comparison.

DXVK_HUD=devinfo,fps,frametimes,compiler shows the selected device, frame-time graph and compiler activity when DXVK is rendering.

Requirements, side effects and removal

Requires: A confirmed Direct3D 9–11 path using DXVK through Wine or Proton. It does not inspect VKD3D-Proton’s Direct3D 12 path or a native Vulkan renderer.

Side effects: The HUD overlays the image; compiler activity is evidence to correlate with a stall, not a diagnosis by itself. GPU-load estimates can be inaccurate.

Remove: Remove DXVK_HUD=devinfo,fps,frametimes,compiler and restart the game.

PROTON_USE_WINED3D=1 substitutes WineD3D for DXVK for one Proton test. A changed outcome narrows the rendering path; it does not identify the defective component.

Requirements, side effects and removal

Requires: Proton and a confirmed Direct3D 9, 10 or 11 game. A working OpenGL driver is required. This is not a Direct3D 12 fallback.

Side effects: Performance and image correctness can change substantially. Vulkan-only diagnostics and the DXVK HUD do not inspect this substituted renderer.

Remove: Remove PROTON_USE_WINED3D=1 and restart the game to restore Steam’s default renderer selection.

VK_LOADER_DEBUG=error,warn,info records desktop Vulkan loader discovery and initialization messages.

Requirements, side effects and removal

Requires: A path that calls the desktop Vulkan loader. Capture Steam’s terminal output or the game’s existing log; this variable does not create a dedicated file by itself. Wine/Proton loader behavior depends on the bundled runtime.

Side effects: Verbose output can affect timing and includes library paths. An individual discovery warning may be harmless when a later driver initializes.

Remove: Remove VK_LOADER_DEBUG=error,warn,info and restart the game.

%command%

    A minimal Proton logging test
    PROTON_LOG=1 %command%

    For a Steam game actually using Proton. It creates a diagnostic log and adds logging overhead; the exact destination depends on the runtime. Remove PROTON_LOG=1 after the test. The log may contain private paths and identifiers. The builder never changes Steam.

    05

    Performance & Frame-Time Troubleshooting

    Average FPS hides brief stalls. Compare frame times during the same reproducible scene and use per-core CPU load, GPU use, VRAM and I/O as context. A single snapshot cannot establish a bottleneck or a hardware fault.

    Optional measurements from the affected moment. Leave anything unknown empty. MangoHud readouts are evidence from that application; CPU I/O wait is a separate host measurement.

    What a useful comparison records

    Record the scene, resolution, render scale / FSR mode, FPS cap, VSync, Gamescope use, graphics API and Proton build. Keep those fixed while testing one setting. Lower render resolution can test GPU pressure; it cannot fix a kernel reset or prove the CPU is at fault.

    Repeat first-pass stutter before clearing caches. For thermal or power suspicion, observe clocks and temperatures at the same timestamps; a low power reading during a stall may be its consequence. Movement-related stalls also require storage and memory evidence.
