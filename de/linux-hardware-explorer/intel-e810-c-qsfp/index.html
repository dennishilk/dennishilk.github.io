Ethernet und Netzwerk

Intel E810-C QSFP-Funktion

Die physische QSFP-Funktion des E810-C verwendet ice. Das DDP-Paket ist eine gesonderte vom Host geladene Komponente und von der Firmware auf dem Netzwerkadapter zu unterscheiden.

Überblick und Identität

Der Header bezeichnet 1592 ausdrücklich als E810C_QSFP. Benachbarte E810-C-Kennungen für Backplane und SFP sind andere; Portgeschwindigkeit und Anordnung folgen nicht allein aus dem Hersteller.

Kuratierte Kennungen
pci 8086:1592

Ein numerischer Match belegt eine Kandidatenfamilie im geprüften Quellenrahmen. Verkaufsnamen, Platinenvarianten, Subsystembedingungen und erfolgreiche Funktion bleiben getrennte Fragen.

Treiber und Bindung

Die ice-Tabelle akzeptiert diese ID. Laut Anleitung kann fehlendes oder ungültiges DDP zum Safe Mode mit eingeschränkten Funktionen führen; das ist von einem vollständig fehlenden PCI-Treiber zu unterscheiden.

  • ice — Kernel-Treiber-/Modulkandidat

Erkannt, gebunden, funktionsfähig: Unterschiede verstehen

Firmware

Bedingter Firmwareweg

Die Upstream-Anleitung dokumentiert intel/ice/ddp/ice.pkg als standardmäßige DDP-Suche. Ein gerätespezifisches Paket kann Vorrang haben. Fehlendes DDP kann einfaches Netzwerk im Safe Mode belassen; Adapter-NVM ist getrennt.

Geprüfte Beispiele oder Dateinamen-Zweige, keine vollständige Installationsliste:

  • intel/ice/ddp/ice.pkg

Lesende Diagnose

Führe jeden angezeigten Befehl einzeln aus. Ersetze Großbuchstaben-Platzhalter durch betroffenes Gerät, Schnittstelle oder Modul aus deiner Ausgabe. Hier wird nichts ausgeführt. Auch lesende Ausgaben können private Kennungen enthalten.

PCI-Funktion und gebundenen Treiber prüfen

lspci -nnk -s BDF

BDF durch die Adresse Domain:Bus:Gerät.Funktion ersetzen. Auf [8086:1592] und Kernel driver in use achten. ice unter Kernel modules ist nur ein Kandidat, kein Bindungsnachweis.

Treiber der Netzwerkschnittstelle feststellen

ethtool -i INTERFACE

INTERFACE durch den echten Schnittstellennamen ersetzen. Driver und bus-info ordnen die Schnittstelle ihrem Gerät zu. Eine firmware-version ist eine Adapterangabe und kein Nachweis für eine geladene Datei. Kandidat: ice.

Unterstützte Modi mit dem aktuellen Link vergleichen

ethtool INTERFACE

Supported/advertised link modes beschreiben Fähigkeiten oder angebotene Modi. Speed, Duplex und Link detected beschreiben den aktuellen Link, keinen gemessenen Durchsatz. Eine nicht unterstützte Abfrage ist eine Schnittstellen-/Treibergrenze.

PCIe-Transport von Ethernet-Geschwindigkeit trennen

sudo lspci -vv -s BDF

Erhöhte Rechte können nötig sein. Root-Rechte können die vollständige PCI-Konfiguration zugänglich machen. Falls PCIe-Felder vorhanden sind, LnkCap mit LnkSta vergleichen: maximale und ausgehandelte PCIe-Geschwindigkeit/Breite sind von Ethernet zu unterscheiden. Altes PCI oder virtuelle Funktionen können die Felder auslassen.

Initialisierung und Firmwareanforderungen ansehen

sudo journalctl -k -b --no-pager

Erhöhte Rechte können nötig sein. Root liest das Kerneljournal des aktuellen Starts. Diesen Controller bzw. diese Schnittstelle sowie den tatsächlich angeforderten Dateinamen oder die Safe-Mode-Meldung suchen. Modulweite Firmwareangaben beweisen keine Anforderung jeder Datei für dieses Gerät.

Grenzen und passende Fehlerhilfen

Grundlegendes Netzwerk im Safe Mode beweist keine verfügbaren erweiterten Offload- oder Leistungsfunktionen. Ein PCI-Treffer validiert außerdem kein eingesetztes QSFP-Modul oder die Switch-Konfiguration.

Diese Anleitungen passen zu relevanten Befunden und behaupten keinen Fehler bei jedem Gerät dieser Familie.

  • Ethernet ohne Carrier oder mit wiederholtem Linkverlust · Erster dokumentierter Hinweis
  • Netzwerk-Sendewarteschlange oder Hardware hängt · Erster dokumentierter Hinweis
