Speichercontroller

LSI SAS2008

SAS2008 ist eine Fusion-MPT-SAS2-Controllerfamilie. Die fixierte Quelle behandelt sie innerhalb von mpt3sas; alte mpt2sas-Namen können weiterhin in interner Treiber-/Proc-Identität erscheinen.

Überblick und Identität

1000:0072 entspricht SAS2008. Die Kennung benennt keine genaue umgelabelte HBA-Karte, bestimmt keine IT-/IR-Firmwarefunktion und identifiziert keine Laufwerke hinter einem Expander.

Kuratierte Kennungen
pci 1000:0072

Ein numerischer Match belegt eine Kandidatenfamilie im geprüften Quellenrahmen. Verkaufsnamen, Platinenvarianten, Subsystembedingungen und erfolgreiche Funktion bleiben getrennte Fragen.

Treiber und Bindung

Das aktuelle Quellen-Makefile baut mpt3sas.ko; dessen genaue Tabelle enthält SAS2008. Die alte Konfiguration SCSI_MPT2SAS wählt SCSI_MPT3SAS; ein historischer Name beweist kein eigenes installiertes Modul.

  • mpt3sas — Kernel-Treiber-/Modulkandidat

Firmware

Geräte- und revisionsabhängig

Controller-Firmware, Option-ROM und Laufwerksfirmware können getrennt sein. Die geprüften Quellen legen für dieses Profil keinen vom Betriebssystem geladenen Dateinamen fest; Firmwarestand und Aktualisierungsregeln benötigen die echte Controller- und OEM-Identität.

Lesende Diagnose

Führe jeden angezeigten Befehl einzeln aus. Ersetze Großbuchstaben-Platzhalter durch betroffenes Gerät, Schnittstelle oder Modul aus deiner Ausgabe. Hier wird nichts ausgeführt. Auch lesende Ausgaben können private Kennungen enthalten.

PCI-Funktion und gebundenen Treiber prüfen

lspci -nnk -s BDF

BDF durch die Adresse Domain:Bus:Gerät.Funktion ersetzen. Auf [1000:0072] und Kernel driver in use achten. mpt3sas unter Kernel modules ist nur ein Kandidat, kein Bindungsnachweis.

Sichtbare Blockgeräte identifizieren

lsblk -d -o NAME,MODEL,TRAN,HCTL

MODEL beschreibt ein Blockgerät oder ein vom Controller präsentierter logischer Datenträger; es ist keine PCI-Controlleridentität. HCTL unterscheidet SCSI-Ziele. TRAN kann fehlen; die Liste beweist keine vollständige physische Datenträgertopologie.

Controller- und Transportmeldungen lesen

sudo journalctl -k -b --no-pager

Erhöhte Rechte können nötig sein. Root liest das Kerneljournal des aktuellen Starts. Meldungen von mpt3sas, Port-/Hostkennungen und Zeitpunkte von Timeouts/Resets dem tatsächlichen Controller zuordnen. Ein Reset allein beweist keinen defekten Datenträger oder Firmwarefehler.

Grenzen und passende Fehlerhilfen

OEM-Subsystem und vorhandene Firmware werden vor Aussagen über einen bestimmten HBA benötigt. Dieses Profil empfiehlt weder Cross-Flashing noch Löschen von RAID-Metadaten oder pauschale Zuordnung jedes SCSI-Timeouts zum Controller.

Diese Anleitungen passen zu relevanten Befunden und behaupten keinen Fehler bei jedem Gerät dieser Familie.

  • PCIe-AER meldet korrigierte oder unkorrigierte Fehler · Erster dokumentierter Hinweis
  • Hintergrundschreibvorgänge bremsen Vordergrundarbeit · Erster dokumentierter Hinweis
