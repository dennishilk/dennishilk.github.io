Fehlende 32-Bit-Vulkan-Unterstützung prüfen

Ein erfolgreicher 64-Bit-Test reicht für einen Prozess mit anderer Loader- und Treiberarchitektur nicht aus.

Programm und Unix-Prozess unterscheiden

Ein klassischer 32-Bit-Wine-Renderprozess braucht passende 32-Bit-Versionen von Vulkan-Loader, ICD-Bibliothek und eingebundenen Layern. Ein 64-Bit-Prozess braucht deren 64-Bit-Versionen. Das Windows-Spiel kann zudem einen Launcher anderer Architektur starten. Neuere WoW64-Anordnungen erschweren dies: PE32 beschreibt das Windows-Programm, beweist allein aber keinen 32-Bit-Unix-Grafikprozess. Bestimme Runner-Architektur und tatsächlich gescheiterten Bibliotheksaufruf. Das normale vulkaninfo prüft auf einem x86_64-Desktop häufig ausschließlich den 64-Bit-Pfad.

Architekturwarnungen im Kontext lesen

Kann die benötigte libvulkan.so.1 oder das gewählte ICD nicht geladen werden, ist eine Architekturprüfung sinnvoll. Eine ignorierte wrong ELF class-Warnung zu Steams gameoverlayrenderer.so ist schwächer: Steam kann beide Overlay-Architekturen versuchen, sodass die unpassende übersprungen wird. Nicht jede ELF-Warnung begründet eine Grafikpaket-Installation. Prüfe die vom scheiternden Prozess genannte Bibliothek, akzeptierte Alternativen und eine möglicherweise anschließende erfolgreiche Geräteerstellung. Logs eines Starts zusammenhalten, damit ein erfolgreicher 64-Bit-Launcher den scheiternden Spielprozess nicht verdeckt.

Die passende Laufzeit statt eines geratenen Pakets reparieren

Nutze die Distributionsdokumentation für gewählten Treiber und benötigte Architektur. Arch-Multilib, Debian- oder Ubuntu-Multiarch und Fedora-Multilib haben unterschiedliche Paketnamen und Regeln. Bei Flatpak-Steam muss auch die Grafiklaufzeit zum Hosttreiber passen. Unter NixOS ist hardware.graphics.enable32Bit deklarative Konfiguration; eine nix-shell mit vorübergehendem vulkaninfo aktiviert keine systemweiten 32-Bit-Grafikbibliotheken. Prüfe die Option für die festgelegte NixOS-Ausgabe und baue erst nach belegter fehlender Architektur aus einer gesicherten Konfiguration neu. Keine Paketmanager vermischen oder Hostbibliotheken in einen Container kopieren.

Vor Änderungen Hinweise sammeln

Führe jeden Befehl einzeln in der passenden Host- oder Spielumgebung aus. Lies zuerst Voraussetzungen und Einordnung. Die Website zeigt Befehle an und führt sie niemals aus.

Lesende Beobachtung

file "/path/to/game.exe"

Voraussetzungen: Platzhalter durch ein echtes Programm ersetzen; file muss installiert sein.

PE32 und PE32+ helfen bei der Windows-Programmidentifikation. Auch den Launcher prüfen, falls sein Fehler vorliegt; das Ergebnis ist nicht die Architektur des Unix-Loaders.

Lesende Beobachtung

file "$(command -v vulkaninfo)"

Voraussetzungen: POSIX-kompatible Shell, file und installiertes vulkaninfo.

Architektur dieses Tests lesen. Ein erfolgreiches 64-Bit-ELF-Programm bestätigt keinen separaten 32-Bit-Prozess. Bei einem Wrapper-Skript muss das aufgerufene Programm genauer geprüft werden.

Temporäre Diagnoseumgebung

nix-shell -p vulkan-tools --run "vulkaninfo --summary"

Voraussetzungen: Nix mit konfiguriertem nixpkgs-Channel; dies ist keine deklarative Grafikänderung.

Nur unter NixOS: vorübergehendes Diagnosewerkzeug bereitstellen. Kann Store-Pfade herunterladen und führt gewöhnlich weiterhin einen nativen Architekturtest mit vorhandener Grafikkonfiguration aus.

Ein kontrollierter Test mit Rückweg

Falls verfügbar, einen von der Distribution unterstützten Vulkan-Test der scheiternden Unix-Architektur in derselben Laufzeit verwenden. Vor einer Installation mit nativem Test und Spiel-Loader-Log vergleichen.

Rücknahme: Temporäre Diagnoseshell verlassen. Nach einer späteren NixOS-Konfigurationsänderung die vorherige Konfiguration oder funktionierende Generation wiederherstellen. Paketänderungen anderer Distributionen brauchen ihre eigene dokumentierte Pakettransaktion.

Was der Test nicht belegen kann: Es gibt weder ein universelles vulkaninfo32 noch einen universellen Installationsbefehl. Die Architektur hängt von der Laufzeit ab, nicht allein von Windows-Programm oder Host-CPU.

Quellen und Geltungsbereich

Diese redaktionelle Prüfung verwendet Originalquellen von Projekten und Distributionen. Sie belegt keine auf deiner Hardware reproduzierte Lösung. Installierte Versionen, Spielumgebung und gewählte Grafik-API können das Ergebnis verändern.

  • Khronos Vulkan loader: architecture-error handling

    Eine unpassende ELF-Architektur kann bei der Treibersuche übersprungen werden; entscheidend ist das Gesamtergebnis.

  • Valve Steam for Linux: mixed-architecture overlay warning

    Valves Erklärung trennt ignorierte Preload-Architekturwarnungen von einer fatal fehlenden Grafikabhängigkeit.

  • Official NixOS Wiki: Steam and graphics configuration

    NixOS konfiguriert Steam und Grafikbibliotheken deklarativ; eine Diagnoseshell aktiviert keine Systemtreiber.
