APT kann angeforderte Abhängigkeiten nicht auflösen

Gehaltene Pakete, Pins und gemischte Release-Quellen können Abhängigkeiten blockieren. Kandidatenversionen und simulierte Transaktion vergleichen.

Symptome und Geltungsbereich

  • APT nennt eine nicht installierbare Abhängigkeitsversion.
  • Eine vorgeschlagene Reparatur entfernt unerwartet wichtige Pakete.

Betroffene Umgebung

Debian-/Ubuntu-System mit APT; Simulationen lesen gespeicherte Metadaten und können durch Konfigurations-Leserechte begrenzt sein.

Erkennbare Meldungen (synthetische Beispiele)
E: Unable to correct problems, you have held broken packages.

Die Formulierung beweist keine apt-mark-Haltemarkierung; Kandidaten, Pins und vorherige Abhängigkeitsmeldungen prüfen.

Mögliche Ursachen

Das sind mögliche Erklärungen, keine bestätigte Diagnose. Mehrere unabhängige Fehler können gleichzeitig vorliegen.

  • Ein gehaltenes Paket oder Pin kann eine nötige Abhängigkeit auf einer unpassenden Version halten.
  • Quellen verschiedener Releases oder Drittanbieter können unvereinbare Paketstände anbieten.

Sicher prüfen

Führe jeweils einen Befehl in der passenden Sitzung aus. Lies zuerst die Erklärung. Großgeschriebene Platzhalter brauchen deine Werte; Werkzeuge und Rechte unterscheiden sich je nach Distribution. Die Website zeigt Befehle an und führt sie niemals aus.

Prüfschritt 1

Beide Namen durch das gewünschte Paket und seine im Fehler genannte Abhängigkeit ersetzen; liest gespeicherte Versionen und Prioritäten.

apt-cache policy PACKAGE_NAME DEPENDENCY_NAME

Ergebnis einordnen: Installed, Candidate, Herkunft und Priorität mit der nötigen Version vergleichen. Ein fehlender Kandidat unterscheidet sich von einem durch Pinning abgelehnten.

Prüfschritt 2

PACKAGE_NAME durch das gewünschte Ziel ersetzen. -s simuliert ohne Installation; keine sudo-Änderungen werden ausgeführt.

apt-get -s install PACKAGE_NAME

Ergebnis einordnen: Inst-, Conf- und Remv-Zeilen sowie Abhängigkeitskette prüfen. Ändern sich Quellen oder lokaler Zustand, garantiert die Simulation keine spätere Transaktion.

Prüfschritt 3

Listet ausdrücklich gehaltene Pakete auf, ohne sie freizugeben.

apt-mark showhold

Ergebnis einordnen: Eine gelistete Abhängigkeit stützt einen Haltekonflikt; held broken packages im Fehler beweist keine ausdrückliche Haltemarkierung.

Nächste Schritte nach Befund

Vorgesehene Quellen und Paketkandidaten abstimmen

Wenn policy eine versehentliche fremde Release-Quelle oder einen Pin zeigt, die Konfiguration sichern und nur diese Quelle beziehungsweise diesen Pin auf das vorgesehene unterstützte Release korrigieren. Metadaten erneuern, Simulation wiederholen und nur eine geprüfte Transaktion mit passenden Kandidaten anwenden.

Vorsicht: Abhängigkeiten nicht erzwingen oder Desktop-/Kernel-Entfernung freigeben, nur um eine optionale Anwendung zu installieren.

Wiederherstellung / Rücknahme: Quelle oder Pin aus der Sicherung herstellen; bei bereits geänderten Paketen einen zusammenhängenden Snapshot oder geprüften passenden Paketstand wiederherstellen.

Die konkrete Haltemarkierung oder offenen lokalen Zustand prüfen

Wenn die nötige Abhängigkeit gehalten wird, zuerst den Grund klären, nur diese Markierung freigeben und neu simulieren. Zeigt dpkg --audit stattdessen offene installierte Abhängigkeiten, apt-get -s -f install simulieren und jede Entfernung prüfen, bevor die Verwaltung wirklich repariert.

Vorsicht: Eine gewollte Kompatibilitätsmarkierung kann eine andere Anwendung schützen. Liste gehaltener Pakete samt Versionen vor Änderungen sichern.

Wiederherstellung / Rücknahme: Die ursprüngliche Haltemarkierung wieder setzen; bei nicht sicher als passender Satz umkehrbaren Versionen oder Entfernungen den Snapshot vor der Transaktion herstellen.

Quellen und Prüfung

Diese Anleitung basiert auf Originalquellen von Projekten oder Distributionen und wurde am genannten Datum redaktionell geprüft. Das ist eine Quellenprüfung, kein Nachweis einer auf deiner Hardware reproduzierten Lösung. Log-Beispiele sind synthetische Testdaten. Versionsabhängige Details müssen zur installierten Ausgabe passen.

  • Debian APT: apt-cache policy and package metadata (Projekt- oder Distributionsdokumentation)
  • Debian APT: apt-get simulation and dependency repair (Projekt- oder Distributionsdokumentation)
  • Debian APT: preferences and pin priority (Projekt- oder Distributionsdokumentation)
  • Debian APT: hold state inspection (Projekt- oder Distributionsdokumentation)

Verwandte Probleme

  • APT findet die Release-Datei einer Quelle nicht
  • pacman erhält seine Datenbanksperre nicht
  • pacman vertraut einer Paketsignatur nicht oder kann sie nicht prüfen
