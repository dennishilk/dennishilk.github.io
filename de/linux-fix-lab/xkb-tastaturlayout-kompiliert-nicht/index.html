XKB kann das konfigurierte Tastaturlayout nicht kompilieren

Ein Layout-Tippfehler oder fehlendes Include kann die Tastaturbelegung blockieren. Gewählte Namen prüfen, ohne die aktive Belegung zu ersetzen.

Symptome und Geltungsbereich

  • Der Compositor lehnt eine Tastaturlayout-Einstellung ab.
  • Protokolle nennen ein fehlendes Symbols-Include oder eine gescheiterte Kompilierung.

Betroffene Umgebung

Desktops und Compositoren mit libxkbcommon; xkbcli kommt aus einem distributionsabhängigen Werkzeugpaket. Xorg nutzt andere Include-Pfadregeln.

Erkennbare Meldungen (synthetische Beispiele)
xkbcommon: ERROR: Couldn't find file "symbols/example-layout" in include paths

Layoutcode und Include-Pfad prüfen, bevor Tastaturhardware oder Eingabetreiber geändert werden.

xkbcommon: ERROR: Failed to compile xkb_symbols

Den vorherigen Kompilierungsfehler lesen, um fehlende Includes von eigener ungültiger Syntax zu trennen.

Mögliche Ursachen

Das sind mögliche Erklärungen, keine bestätigte Diagnose. Mehrere unabhängige Fehler können gleichzeitig vorliegen.

  • Ein ausgeschriebener Sprachname kann anstelle eines XKB-Layout- oder Variantencodes stehen.
  • Eine eigene Symbols-Datei oder xkeyboard-config-Ressource kann in den aktiven Include-Pfaden fehlen.

Sicher prüfen

Führe jeweils einen Befehl in der passenden Sitzung aus. Lies zuerst die Erklärung. Großgeschriebene Platzhalter brauchen deine Werte; Werkzeuge und Rechte unterscheiden sich je nach Distribution. Die Website zeigt Befehle an und führt sie niemals aus.

Prüfschritt 1

LAYOUT und VARIANT durch die eingetragenen Codes ersetzen; bei fehlender Variante --variant weglassen. Kompiliert zur Ausgabe, ohne die aktive Tastatur umzustellen.

xkbcli compile-keymap --layout LAYOUT --variant VARIANT

Ergebnis einordnen: Ein Kompilierungsfehler nennt fehlende Symbols-Dateien oder Syntax. Eine erfolgreiche Kompilierung beweist nicht, dass der Compositor dieselbe Konfiguration lädt.

Prüfschritt 2

Liest eigene Include-Pfadvariablen, ohne eine Belegung zu laden. Bei Bedarf die Umgebung des Compositors getrennt prüfen.

printenv XKB_CONFIG_ROOT XKB_CONFIG_EXTRA_PATH XDG_CONFIG_HOME

Ergebnis einordnen: Eine eigene Wurzel kann Distributionslayouts verdecken. Benutzer- und privilegierte Kontexte können andere Pfade durchsuchen; root ist kein gleichwertiger Test.

Nächste Schritte nach Befund

Layout- und Variantencodes korrigieren

Wenn fehlende Symbols-Namen aus einem Tippfehler stammen, die Tastaturkonfiguration sichern und ein installiertes Layout-/Variantenpaar in den Einstellungen wählen. Dieses zuerst kompilieren und dann nur die Tastaturänderung per unterstütztem Neuladen oder Neuanmeldung anwenden.

Vorsicht: Eine funktionierende Ersatzbelegung und einen weiteren Eingabe-/Rettungsweg behalten; eine ungültige aktive Belegung kann das Tippen der Rücknahme verhindern.

Wiederherstellung / Rücknahme: Die gesicherten Tastatureinstellungen herstellen und die zuvor funktionierende Belegung über denselben Sitzungsweg anwenden.

Hinweis teilen#

Das konkrete eigene Include oder Ressourcenpaket korrigieren

Wenn ein eigenes Layout gewollt ist, nur dessen fehlende Ressource am dokumentierten Benutzer-Include-Ort ergänzen und vor Aktivierung aus einem temporären Include-Pfad testen. Bei fehlenden Standardlayouts das zuständige xkeyboard-config-Paket über die Distribution reparieren.

Vorsicht: Keine System-Symbols-Dateien überschreiben oder annehmen, dass Xorg die Benutzerpfade von libxkbcommon berücksichtigt.

Wiederherstellung / Rücknahme: Die ergänzte eigene Ressource entfernen oder deren gesicherte Version und die ursprüngliche Include-Pfadregel wiederherstellen.

Quellen und Prüfung

Diese Anleitung basiert auf Originalquellen von Projekten oder Distributionen und wurde am genannten Datum redaktionell geprüft. Das ist eine Quellenprüfung, kein Nachweis einer auf deiner Hardware reproduzierten Lösung. Log-Beispiele sind synthetische Testdaten. Versionsabhängige Details müssen zur installierten Ausgabe passen.

  • libxkbcommon: read-only keymap compilation and debugging (Projekt- oder Distributionsdokumentation)
  • libxkbcommon: custom configuration and include paths (Projekt- oder Distributionsdokumentation)
  • QEMU upstream: missing XKB resource compiler output (Upstream-Fehlerbericht; gemeldetes Verhalten ist keine reproduzierte Lösung)
