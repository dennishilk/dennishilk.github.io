Dateien oder Links öffnen die falsche Standardanwendung

MIME-Vorgaben und desktopspezifische Regeln können eine andere Anwendung wählen. Erkannten Typ, Starter-ID und Vorrang der Regeln vergleichen.

Symptome und Geltungsbereich

  • PDF-Dateien öffnen sich in einem unerwarteten Betrachter.
  • Ein Weblink startet trotz neuer Installation einen alten Browser.

Betroffene Umgebung

MIME-Anwendungszuordnungen nach freedesktop.org; Dateitypen und URL-Schemata besitzen getrennte Bezeichner.

Mögliche Ursachen

Das sind mögliche Erklärungen, keine bestätigte Diagnose. Mehrere unabhängige Fehler können gleichzeitig vorliegen.

  • Eine vorrangige Benutzer- oder Desktop-mimeapps.list kann die Systemvorgabe überschreiben.
  • Die Anwendung kann einen anderen MIME-Typ oder eine URL-Schema-Zuordnung verwenden.

Sicher prüfen

Führe jeweils einen Befehl in der passenden Sitzung aus. Lies zuerst die Erklärung. Großgeschriebene Platzhalter brauchen deine Werte; Werkzeuge und Rechte unterscheiden sich je nach Distribution. Die Website zeigt Befehle an und führt sie niemals aus.

Prüfschritt 1

Durch eine vorhandene repräsentative Datei ersetzen; klassifiziert sie, ohne die zugeordnete GUI-Anwendung zu öffnen.

xdg-mime query filetype /path/to/file

Ergebnis einordnen: Den ausgegebenen Typ für die nächste Abfrage nutzen. Eine Dateiendung allein beweist nicht den vom Desktop verwendeten MIME-Typ.

Prüfschritt 2

MIME_TYPE durch den erkannten Typ wie application/pdf oder das tatsächliche URL-Schema wie x-scheme-handler/https ersetzen.

xdg-mime query default MIME_TYPE

Ergebnis einordnen: Die Ausgabe ist eine Desktop-Datei-ID, kein Programmpfad. Keine Ausgabe spricht für keine ermittelte Vorgabe; eine App kann trotzdem eine eigene Zuordnung wählen.

Nächste Schritte nach Befund

Die Vorgabe für den tatsächlichen MIME-Typ setzen

Wenn die ermittelte Vorgabe falsch ist, deren Desktop-Datei-ID notieren und die vorgesehene installierte Anwendung über die Standardprogrammeinstellungen oder xdg-mime default APP.desktop MIME_TYPE wählen. Bei Weblinks das HTTPS-Schema getrennt ändern.

Vorsicht: Eine tatsächlich installierte Desktop-Datei-ID verwenden. Nicht alle Dateitypen einer einzigen Anwendung zuweisen.

Wiederherstellung / Rücknahme: Die notierte Desktop-Datei-ID für denselben MIME-Typ herstellen oder die gesicherte mimeapps.list nutzen, wenn vorher keine ausdrückliche Zuordnung bestand.

Hinweis teilen#

Eine veraltete vorrangige Zuordnung korrigieren

Wenn die neue Vorgabe sofort überschattet wird, Benutzer-mimeapps.list und desktopspezifische Vorgaben des aktiven Desktops prüfen. Die betreffende Datei sichern und nur den alten Default-Applications-Eintrag dieses Typs korrigieren; Added und Removed Associations erhalten.

Vorsicht: Konfigurationsorte haben einen Vorrang; eine niedrig priorisierte Systemdatei beeinflusst eine Benutzer-Vorgabe möglicherweise nicht.

Wiederherstellung / Rücknahme: Die gesicherte Zuordnungsdatei oder den ursprünglichen Eintrag dieses Typs herstellen, ohne andere Vorgaben zu ersetzen.
