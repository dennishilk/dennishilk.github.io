NVIDIA-Modul fehlt nach einem Kernel-Update

Nach einem Kernel-Update kann das NVIDIA-Modul fehlen, obwohl Treiberpakete installiert sind. Zuerst Kernel und Modulpakete abgleichen.

Symptome und Geltungsbereich

  • Nach einem Update startet der Desktop mit einfacher Anzeige oder der Display-Manager scheitert.
  • modprobe meldet, dass das NVIDIA-Modul für den laufenden Kernel nicht vorhanden ist; nvidia-smi kann ebenfalls scheitern.

Betroffene Umgebung

Ubuntu und verwandte Distributionen mit paketierten NVIDIA-Modulen oder DKMS; Fedora nutzt einen anderen akmods-Weg. Nur bei belegtem Modulfehler anwenden.

Erkennbare Meldungen (synthetische Beispiele)
modprobe: FATAL: Module nvidia not found in directory /lib/modules/7.0.0-30-generic

Laufenden Kernel und passendes Modulpaket vor Signatur-, Hardware- oder Vulkanverdacht prüfen.

Mögliche Ursachen

Das sind mögliche Erklärungen, keine bestätigte Diagnose. Mehrere unabhängige Fehler können gleichzeitig vorliegen.

  • Ein vorgefertigtes NVIDIA-Modulpaket kann für die tatsächlich gestartete Kernel-ABI fehlen, obwohl eine ältere Version installiert ist.
  • Ein DKMS-Build kann wegen fehlender Kernel-Header oder Build-Abhängigkeiten unvollständig sein. Das ist etwas anderes als die Ablehnung eines vorhandenen unsignierten Moduls durch Secure Boot.

Sicher prüfen

Führe jeweils einen Befehl in der passenden Sitzung aus. Lies zuerst die Erklärung. Großgeschriebene Platzhalter brauchen deine Werte; Werkzeuge und Rechte unterscheiden sich je nach Distribution. Die Website zeigt Befehle an und führt sie niemals aus.

Prüfschritt 1

Aktuell gestartete Kernelversion ohne Paketänderung anzeigen.

uname -r

Ergebnis einordnen: Das NVIDIA-Modul muss zu diesem Kernel passen, nicht nur zum neuesten installierten Kernel.

Prüfschritt 2

kmod nach dem Modulpfad für den laufenden Kernel fragen; dieser Befehl lädt kein Modul.

modinfo -n nvidia

Ergebnis einordnen: Ein fehlender Pfad stützt ein Modulpaketproblem. Ein gefundener Pfad beweist weder erfolgreiches Laden noch passende Userspace-Version.

Prüfschritt 3

Nur nutzen, wenn DKMS installiert ist; auf Ubuntu kann ein vorgefertigtes Modul ohne DKMS-Eintrag existieren.

dkms status

Ergebnis einordnen: Build-/Installationsstatus beziehen sich auf einzelne Kernelversionen. Kein DKMS-Eintrag beweist keinen NVIDIA-Fehler.

Nächste Schritte nach Befund

Kernel-ABI und passendes Modulpaket vergleichen

Auf Ubuntu das installierte linux-modules-nvidia-Paket für die aktive Treiberreihe und die konkrete Kernel-ABI mit der Paketverwaltung vergleichen. Vor Änderungen klären, ob vorgefertigte Module oder DKMS vorgesehen sind. Den unterstützten Ubuntu-Installationsweg und passende Treiberserien bevorzugen, keine beliebigen .run-Installer.

Vorsicht: Vorher funktionierenden Kernel-Starteintrag behalten; nicht wegen einer einzelnen nvidia-smi-Meldung pauschal alle Grafikpakete löschen.

Wiederherstellung / Rücknahme: Bei Bedarf den zuvor funktionierenden Kernel starten; nur gezielte Paketänderungen zurücknehmen.

Hinweis teilen#

Secure Boot getrennt vom fehlenden Modul prüfen

Findet modinfo ein Modul, scheitert aber dessen Laden, zuerst Journal und Signatur prüfen. Ubuntu prüft im Secure-Boot-Betrieb Signaturen von Drittmodulen; ein vorhandenes, wegen Vertrauensregeln abgelehntes Modul verlangt eine MOK-/Signaturdiagnose, keine willkürliche Neuinstallation. Ein für den laufenden Kernel fehlendes Modul entsteht nicht durch Abschalten von Secure Boot.

Vorsicht: Secure Boot nicht standardmäßig ausschalten; das verändert eine Sicherheitsgrenze.

Wiederherstellung / Rücknahme: Secure-Boot-Konfiguration beibehalten und den dokumentierten MOK-Weg nur bei belegtem Signaturproblem nutzen.

Quellen und Prüfung

Diese Anleitung basiert auf Originalquellen von Projekten oder Distributionen und wurde am genannten Datum redaktionell geprüft. Das ist eine Quellenprüfung, kein Nachweis einer auf deiner Hardware reproduzierten Lösung. Log-Beispiele sind synthetische Testdaten. Versionsabhängige Details müssen zur installierten Ausgabe passen.

  • Ubuntu: install and match NVIDIA kernel modules (Projekt- oder Distributionsdokumentation)
  • Ubuntu: DKMS build and Secure Boot boundaries (Projekt- oder Distributionsdokumentation)
  • Ubuntu: UEFI Secure Boot and module signing (Projekt- oder Distributionsdokumentation)

Verwandte Probleme

  • NVIDIA-Modul wird wegen seiner Signatur abgelehnt
  • NVIDIA Xid 79: GPU ist über PCIe nicht mehr erreichbar
  • NVIDIA-Treiber und Userspace-Bibliotheken passen nicht zusammen
