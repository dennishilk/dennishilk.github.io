Nouveau belegt die für NVIDIA vorgesehene GPU

Eine GPU kann nur einem Kerneltreiber gehören; aktive PCI-Bindung prüfen, bevor Nouveau-Sperrlisten oder das frühe Startabbild geändert werden.

Symptome und Geltungsbereich

  • nvidia-smi findet kein nutzbares Gerät, während der Desktop Nouveau verwendet.
  • NVIDIA-Initialisierung scheitert nach einem unvollständigen Treiberwechsel.

Betroffene Umgebung

Systeme, die eine unterstützte NVIDIA-GPU von Nouveau auf den NVIDIA-Treiber umstellen; ein installiertes Nouveau ist für sich kein Fehler.

Mögliche Ursachen

Das sind mögliche Erklärungen, keine bestätigte Diagnose. Mehrere unabhängige Fehler können gleichzeitig vorliegen.

  • Nouveau kann die GPU bereits aus der Initramfs binden, bevor NVIDIA lädt.
  • Eine bewusst gewählte Nouveau-/NVK-Konfiguration kann korrekt funktionieren; eine Umstellung ist nur beim gewählten unterstützten NVIDIA-Treiber begründet.

Sicher prüfen

Führe jeweils einen Befehl in der passenden Sitzung aus. Lies zuerst die Erklärung. Großgeschriebene Platzhalter brauchen deine Werte; Werkzeuge und Rechte unterscheiden sich je nach Distribution. Die Website zeigt Befehle an und führt sie niemals aus.

Prüfschritt 1

Ziel-GPU suchen und Kernel driver in use lesen; kein Treiber wird entladen.

lspci -nnk

Ergebnis einordnen: nouveau an dieser Stelle belegt aktive Belegung. Beide Namen unter Kernel modules zeigen nur mögliche Module, keine gleichzeitige Belegung.

Prüfschritt 2

Zusammengeführte Modul-Laderichtlinien anzeigen; benötigt ripgrep. Konfiguration wird gelesen, keine Module werden geladen.

modprobe --showconfig | rg 'nouveau|nvidia'

Ergebnis einordnen: Eine hier fehlende Sperrregel beeinflusst automatisches Laden nicht; eine vorhandene Regel kann in der gewählten Initramfs fehlen oder durch ausdrückliches Laden umgangen werden.

Nächste Schritte nach Befund

Einen unterstützten Treiberpfad wählen

Ist Nouveau beabsichtigt und funktioniert, behalten und nvidia-smi nicht als dessen Funktionstest verwenden. Wird NVIDIA gebraucht, zuerst das GPU-kompatible NVIDIA-Paket der Distribution installieren, bevor frühes Nouveau-Binden verhindert wird.

Vorsicht: Nouveau nicht aus einer aktiven Grafiksitzung entladen und den einzigen funktionierenden Grafikpfad nicht vor einem fertigen Ersatz entfernen.

Wiederherstellung / Rücknahme: Vorherige Paketkonfiguration und Starteintrag verwenden, falls der gewählte Ersatz keine Bildausgabe liefert.

Treiberwahl ins frühe Startabbild übernehmen

Ist der Ersatz bereit, die Nouveau-Sperrregel der Distribution anwenden und genau die GPU ladende Initramfs erneuern. Nach Neustart PCI-Bindung erneut prüfen; Laufzeitkonfiguration allein erreicht den frühen Start eventuell nicht.

Vorsicht: Neue Konfigurationsdateien dokumentieren und Rettungskonsole oder älteres Abbild behalten. nouveau.modeset=0 allein garantiert keine NVIDIA-Belegung.

Wiederherstellung / Rücknahme: Nur die hinzugefügte lokale Sperrregel entfernen, vorherige Treiberpaketwahl wiederherstellen und dieselbe Initramfs vor Neustart erneuern.
