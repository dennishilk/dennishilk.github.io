Anwendung läuft auf der falschen GPU

Hybridgrafik trennt Bildausgabe und Rendering; Geräteauswahl je API vergleichen, bevor der gesamte Desktop auf eine andere GPU gezwungen wird.

Symptome und Geltungsbereich

  • Eine Anwendung nutzt trotz verfügbarer separater GPU die integrierte Grafik.
  • Ein Monitor an einer GPU funktioniert, während eine Rendering-Anwendung eine andere wählt.

Betroffene Umgebung

Mehr-GPU-Systeme mit Mesa PRIME oder NVIDIA Render Offload; Offload-Unterstützung hängt von Treiber und Sitzung ab.

Mögliche Ursachen

Das sind mögliche Erklärungen, keine bestätigte Diagnose. Mehrere unabhängige Fehler können gleichzeitig vorliegen.

  • Standard-Reihenfolge oder Auswahlregel der Anwendung kann integrierte Grafik bevorzugen.
  • OpenGL und Vulkan können unterschiedliche Offload-Schalter nutzen; die Belegung des Bildschirmanschlusses belegt keine Rendering-GPU.

Sicher prüfen

Führe jeweils einen Befehl in der passenden Sitzung aus. Lies zuerst die Erklärung. Großgeschriebene Platzhalter brauchen deine Werte; Werkzeuge und Rechte unterscheiden sich je nach Distribution. Die Website zeigt Befehle an und führt sie niemals aus.

Prüfschritt 1

Alle Grafikcontroller und aktiven Treiber auflisten; keine administrativen Änderungen werden vorgenommen.

lspci -nnk

Ergebnis einordnen: Beide GPUs brauchen einen passenden aktiven Treiber für nutzbares Offload. Eine ungebundene GPU wird durch eine Umgebungsvariable allein nicht nutzbar.

Prüfschritt 2

Vulkan-Gerätenamen in der Anwendungs-Laufzeit lesen; benötigt vulkaninfo.

vulkaninfo --summary

Ergebnis einordnen: Mehrere Geräte ermöglichen Anwendungs-Auswahl; die Reihenfolge allein beweist jedoch keine tatsächliche Auswahl der Anwendung.

Nächste Schritte nach Befund

Mesa-GPU für eine Anwendung wählen

Sind beide Mesa-unterstützten GPUs aufgeführt, den dokumentierten DRI_PRIME-Selektor im Starter der Anwendung testen. Eigenen Renderer der Anwendung prüfen; Vulkan kann die Selektorform benötigen, die andere Geräte ausblendet.

Vorsicht: Die Einstellung je Anwendung statt global setzen. Auch eine gewählte GPU benötigt Laufzeit- und Gerätezugriff; PCI-Bindung nicht ändern.

Wiederherstellung / Rücknahme: Hinzugefügten DRI_PRIME-Parameter aus dem Starter entfernen, um die normale Gerätewahl wiederherzustellen.

Unterstütztes NVIDIA Render Offload nutzen

Soll NVIDIA rendern, dessen dokumentierte PRIME-Offload-Variablen für die jeweilige API nutzen: OpenGL GLX braucht auch die NVIDIA-Anbieterwahl, Vulkan nutzt die NVIDIA-Offload-Schicht. Anleitung der installierten Version prüfen.

Vorsicht: Xorg-Beispiele nicht als vollständige Wayland-Konfiguration ansehen. Den gesamten Desktop auf die separate GPU zu zwingen kann Akkulaufzeit und externe Monitore beeinflussen.

Wiederherstellung / Rücknahme: Nur hinzugefügte Offload-Variablen entfernen und zum ursprünglichen Anwendungsprofil zurückkehren.
