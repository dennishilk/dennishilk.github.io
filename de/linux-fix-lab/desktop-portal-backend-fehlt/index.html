Ein Desktop-Portal kann sein Backend nicht aktivieren

Fehlende Dateiauswahl oder Bildschirmfreigabe kann an der Portalwahl liegen. Backend-Unterstützung und Desktop-Sitzungsumgebung prüfen.

Symptome und Geltungsbereich

  • Eine Sandbox-Anwendung hängt beim Öffnen der Dateiauswahl.
  • Bildschirmfreigabe zeigt keinen Auswahl-Dialog oder einen Backend-Aktivierungsfehler.

Betroffene Umgebung

Desktop mit xdg-desktop-portal; Backend-Fähigkeiten unterscheiden sich, Dateiauswahl und Bildschirmaufnahme können verschiedene Backends nutzen.

Erkennbare Meldungen (synthetische Beispiele)
xdg-desktop-portal[510]: Failed to create file chooser proxy: Error calling StartServiceByName for org.freedesktop.impl.portal.desktop.gnome: Timeout was reached

Dieses Backend und die Sitzung prüfen; die Zeile rechtfertigt keine erweiterten Dateisystemrechte der Sandbox.

xdg-desktop-portal[510]: Failed to create screenshot proxy: Error calling StartServiceByName for org.freedesktop.impl.portal.desktop.wlr: Timeout was reached

Schnittstellenunterstützung, Aktivierung und Compositor-Umgebung prüfen; daraus allein keinen GPU-Fehler ableiten.

Mögliche Ursachen

Das sind mögliche Erklärungen, keine bestätigte Diagnose. Mehrere unabhängige Fehler können gleichzeitig vorliegen.

  • Eine desktopspezifische Portalregel kann ein fehlendes Backend wählen.
  • Der Backend-Prozess kann eine veraltete Desktop- oder Display-Umgebung erben.

Sicher prüfen

Führe jeweils einen Befehl in der passenden Sitzung aus. Lies zuerst die Erklärung. Großgeschriebene Platzhalter brauchen deine Werte; Werkzeuge und Rechte unterscheiden sich je nach Distribution. Die Website zeigt Befehle an und führt sie niemals aus.

Prüfschritt 1

Liest Dienststatus und letzte Meldungen im betroffenen Desktop-Konto; gilt für systemd-Benutzersitzungen.

systemctl --user status xdg-desktop-portal.service --no-pager

Ergebnis einordnen: Das genannte org.freedesktop.impl.portal-Backend und die fehlerhafte Schnittstelle prüfen. Ein laufendes Frontend beweist kein verfügbares Backend.

Prüfschritt 2

Liest Benutzer-Vorgaben und installierte Portaldefinitionen; bei eigenem XDG_CONFIG_HOME den Benutzerpfad anpassen.

rg -n "preferred|default=|FileChooser=|ScreenCast=|Interfaces=|UseIn=" "$HOME/.config/xdg-desktop-portal" /usr/share/xdg-desktop-portal

Ergebnis einordnen: Vorrang und tatsächlich unterstützte Schnittstelle prüfen. Mehrere installierte Backends wählen nicht automatisch das richtige aus.

Nächste Schritte nach Befund

Installierte Backends für die benötigten Schnittstellen wählen

Wenn die Konfiguration ein fehlendes oder ungeeignetes Backend wählt, die Benutzer-portals.conf sichern und passende installierte Anbieter für FileChooser beziehungsweise ScreenCast wählen. Falls nötig das passende Distributions-Backend installieren und Portaldienste nach Schließen aktiver Anfragen neu starten.

Vorsicht: Ein wlroots-Aufnahmebackend bietet möglicherweise keine Dateiauswahl. Andere Desktop-Backends nicht pauschal entfernen.

Wiederherstellung / Rücknahme: Die gesicherte Benutzer-portals.conf wiederherstellen oder nur die neue Vorgabe entfernen; anschließend dieselben Portaldienste neu starten.

Hinweis teilen#

Den Portalen übergebene Sitzungsumgebung korrigieren

Wenn das Backend installiert ist, aber einen anderen Desktop oder ein anderes Display erwartet, die dokumentierte Sitzungsintegration des Compositors für DISPLAY, WAYLAND_DISPLAY und XDG_CURRENT_DESKTOP korrigieren. Konfiguration sichern und neu anmelden, damit betroffene Dienste die vorgesehenen Werte erhalten.

Vorsicht: Nicht wahllos alle Umgebungsvariablen importieren; mehrere gleichzeitige Desktops desselben Kontos können einen Benutzermanager teilen.

Wiederherstellung / Rücknahme: Die gesicherte Sitzungsintegration wiederherstellen und neu anmelden; einen störenden temporären Desktop mit gemeinsamen Werten beenden.
