Arch Linux trifft Windows 98 SE: Mein Retro-LAN zwischen Cthulhu und 1999

Von Dennis Hilk · 21. November 2026

Ein Pentium III von 1999, Windows 98 SE, eine Realtek-Netzwerkkarte und mein moderner Arch-Linux-Rechner Cthulhu. Können die beiden 2026 noch miteinander reden? Ja! Nach ein paar Umwegen steht die Samba-Freigabe – und Winamp spielt wieder Musik. Berta und Bigmac überwachen den Desktop. 😄

Die Ausgangslage: echte Hardware statt VM

Mein Yakumo-Retro-PC läuft mit Windows 98 SE, einem Intel Pentium III Katmai mit 500 MHz und 128 MB SDRAM. AIDA32 v3.94.2 identifizierte jetzt die Basishardware: TriGem NAPOLI mit Intel 440BX/ZX, ATI 3D Rage Pro (8 MB), Realtek RTL8029(AS) und Aureal Vortex 1 AU8820B2. Das CD-Laufwerk ist ein Plextor PX-40TS.

Die Aztech-Soundkarte und die S3-Grafikkarte sind bei diesem Test ausgebaut, das Iomega Zip ist nicht angeschlossen. Der Anlass für diese ganze Retro-Rettungsaktion war meine originale Big Box von Jane’s AH-64D Longbow (1996).

Das Kabel: Cthulhu bekommt ein eigenes Retro-Netz

Der Yakumo hängt über ein direktes Ethernet-Kabel an der zweiten Netzwerkkarte meines Arch-Linux-Rechners. enp81s0 ist ausschließlich fürs Retro-LAN da; das normale Netz läuft weiter über enp82s0. Windows 98 bekommt absichtlich weder Gateway noch DNS und bleibt damit ohne Internetzugang.

GerätSchnittstelleStatische IP
Arch Linux / Cthulhuenp81s010.1.2.3/24
Windows 98 / RETRORTL8029(AS)10.1.2.4/24

Das NetworkManager-Profil heißt retro-lan, auf Windows 98 lautet die Subnetzmaske 255.255.255.0. ping funktioniert in beide Richtungen. Das ist die erste Hürde, aber noch nicht der fertige Dateitransfer.

Samba statt FTP: SMB1 nur auf dem Retro-Kabel

Zunächst probierte ich vsftpd. Der FTP-Transfer klappte hier nicht zuverlässig, also entfernte ich den FTP-Server wieder und richtete Samba ein. Windows 98 verwendet in dieser Konfiguration altes NetBIOS-SMB; auf Cthulhu ist Samba gezielt auf SMB1/NT1 und TCP-Port 139 beschränkt.

Die tatsächlich genutzte /etc/samba/smb.conf sieht so aus:

[global]
workgroup = WORKGROUP
netbios name = CTHULHU
server role = standalone server
security = user
map to guest = Bad User
interfaces = lo 10.1.2.3/24
bind interfaces only = yes
hosts allow = 127. 10.1.2.4
hosts deny = ALL
server min protocol = NT1
server max protocol = NT1
smb ports = 139
load printers = no

[RetroShare]
path = /home/nebu/RetroShare
browseable = yes
guest ok = yes
guest only = yes
force user = nebu
read only = no
follow symlinks = no

Das Verzeichnis liegt unter /home/nebu/RetroShare. Unter Windows 98 ist \\10.1.2.3\RetroShare als Netzlaufwerk E: eingebunden. Dateien vom Linux-Rechner öffnen und kopieren funktioniert. Die Schreibfreigabe ist serverseitig aktiviert; ob Windows 98 nach der erneuten Verbindung auch Dateien anlegen und löschen kann, war beim Schreiben noch nicht abschließend erneut getestet.

UFW und die Windows-98-Neustart-Tradition

Samba lauschte bereits korrekt auf 10.1.2.3:139. Trotzdem meldete Windows 98 zunächst, der Rechner sei nicht zu finden. Ein Mitschnitt mit tcpdump zeigte NetBIOS-Anfragen vom Yakumo. Am Ende brauchten wir drei auf Retro-Schnittstelle, Gegenstelle und Port beschränkte UFW-Regeln:

sudo ufw allow in on enp81s0 from 10.1.2.4 to 10.1.2.3 port 137 proto udp
sudo ufw allow in on enp81s0 from 10.1.2.4 to 10.1.2.3 port 138 proto udp
sudo ufw allow in on enp81s0 from 10.1.2.4 to 10.1.2.3 port 139 proto tcp

Danach kam die Verbindung zustande. Als wir Samba später für Schreibzugriff neu luden, verlor Windows 98 sein E:-Laufwerk vorübergehend. Ein Windows-Neustart brachte die Zuordnung zurück. Katharina kam mehrfach am Nachmittag vorbei – und offenbar immer dann, wenn Windows 98 gerade wieder neu startete. 🤣

Winamp spielt – dank Aureal Vortex

Erst kamen Berta und Bigmac als Desktop-Hintergrund. Dann der passende Aureal-Vortex-Windows-9x-Treiber 4.06.1189, ausgewählt anhand des AIDA32-Befunds. Und plötzlich war er da: Ton! Winamp spielte Busta Rhymes & Mariah Carey – I Know What You Want. Auf der Playlist stehen außerdem Ace of Base, Eiffel 65, Oasis und The Offspring. Mehr Jahrtausendwende geht kaum.

Der wichtige Unterschied: Windows-Audio ist jetzt bestätigt. Ob der Aureal-Treiber auch den benötigten digitalen DOS-Sound für Longbow liefert, testen wir als Nächstes im Spiel. Hier steht deshalb noch kein erfundenes Erfolgshäkchen.

Bitte nicht im normalen Heimnetz nachbauen

SMB1 ist veraltet und unsicher. Dieses Setup ist nur vertretbar als isoliertes Retro-Experiment: dediziertes Kabel, feste Quell- und Zieladressen, Bindung an die Retro-Schnittstelle, UFW-Regeln und kein Internetzugang auf Windows 98. Die Freigabe erlaubt Gastzugriff und serverseitiges Schreiben – dort gehören ausschließlich unkritische Austauschdateien hinein.

Das ist mein dokumentierter Einzelfall, keine allgemeine Empfehlung für SMB1 in einem heutigen LAN. Nicht direkt mit dem Internet verbinden und keine privaten Dateien in den Gast-Share legen.

Fazit: Das Computermuseum ist wieder verbunden

Arch Linux und Windows 98 SE reden miteinander. Der Yakumo liest Dateien von Cthulhu über E:, AIDA32 kennt endlich die reale Hardware und Winamp spielt wieder Musik. Berta und Bigmac passen auf, und die Quantum Fireball bekommt ihre Neustarts. ❤️

Wie es mit dem DOS-Sound von Jane’s AH-64D Longbow weitergeht, dokumentiere ich im Longbow-Restaurierungsbericht.
