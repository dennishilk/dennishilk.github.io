Wine-Prefix verstehen: getrennte Windows-Umgebungen unter Linux

Von Dennis Hilk8. Oktober 20266 Minuten Lesezeit
Konfiguration und Spielumgebung lokal halten

Ein Prefix liegt lokal, doch Spiele, Installer und Launcher können online sein. Ein Wine-Prefix trennt Einstellungen und ist keine Sicherheits-Sandbox für unbekannte Windows-Programme.

Ein Spiel benötigt eine andere Einstellung als ein zweites. Wenn beide dieselbe Wine-Umgebung nutzen, beeinflusst eine Änderung möglicherweise beide. Ein eigener Prefix hilft, Registry, installierte Komponenten und virtuelle Windows-Dateien übersichtlich zu trennen.

Dieser Artikel vertieft meinen Linux-Gaming-Guide. Dort geht es um Steam, Proton und Lutris als Gesamtaufbau. Hier schauen wir auf den einzelnen Prefix und testen Wine zunächst mit seiner eigenen Konfigurationsoberfläche, ohne ein fremdes Spielinstallationspaket auszuführen.

Was ist ein Wine-Prefix?

Ein Prefix ist das Verzeichnis, in dem Wine seine Windows-Umgebung verwaltet. Ohne besondere Auswahl ist das üblicherweise ~/.wine. Die Umgebungsvariable WINEPREFIX kann für einen bestimmten Aufruf ein anderes absolutes Verzeichnis festlegen.

Bestandteil Bedeutung
drive_c Virtueller Inhalt von Laufwerk C
dosdevices Zuordnung von Windows-Laufwerken zu Linux-Pfaden
Registry-Dateien Gespeicherte Windows-/Wine-Einstellungen
Installierte Komponenten Beispielsweise zusätzliche Laufzeitbibliotheken

Wine ist dabei kein vollständiges Windows in einer virtuellen Maschine. Es stellt Windows-Schnittstellen für Programme bereit. Das VM-Tutorial beschreibt einen anderen Aufbau mit eigenem Gastbetriebssystem.

Prefix und Wine-Version getrennt betrachten

Der Prefix speichert Einstellungen und installierte Dateien. Die verwendete Wine-Version, oft als Runner bezeichnet, ist eine weitere Entscheidung. Dass ein Ordner existiert, sagt noch nicht, mit welcher Version er zuletzt benutzt wurde.

Lutris kann pro Spiel einen Prefix und einen Runner verwalten. Steam/Proton hält seine eigenen Kompatibilitätsdaten. Starte solche verwalteten Umgebungen nicht probeweise mit einer beliebigen System-Wine-Version. Ein Runner-Wechsel kann Dateien und Einstellungen aktualisieren; sichere wichtige Daten vor Experimenten.

Für den folgenden unkritischen Test genügt installiertes Wine in einer grafischen Linux-Sitzung. Prüfe seine Version:

wine --version

Eine eigene Testumgebung auswählen

Prüfe zuerst, ob ~/wine-tutorial schon eigene Daten enthält. Wähle bei Bedarf einen neuen Namen. Wir verwenden ein neues Verzeichnis und vermeiden damit deinen regulären ~/.wine-Prefix.

Starte die Wine-Konfiguration mit einem ausdrücklich gewählten Prefix:

env WINEPREFIX="$HOME/wine-tutorial" winecfg

env setzt die Variable nur für diesen Aufruf und seine gestarteten Prozesse. Die Schreibweise funktioniert für diesen Befehl auch aus fish, ohne dauerhaft deine Shell-Umgebung zu ändern. Der Pfad ist absolut, weil $HOME zum vollständigen Home-Pfad erweitert wird.

Wine legt bei einer neuen Umgebung seine Verzeichnisstruktur an. Je nach Paket und Version können Vorschläge für zusätzliche Komponenten beziehungsweise Downloads erscheinen. Für die reine Konfigurationsübung brauchst du kein Spielekonto. Lies zusätzliche Installationsangebote, bevor du sie annimmst.

Eine Einstellung ändern und wieder zurücksetzen

In winecfg findest du unter anderem Anwendungen, Bibliotheken, Grafik und Laufwerke. Wähle für die Übung zunächst nur eine gut nachvollziehbare Anzeigeoption, beispielsweise einen virtuellen Desktop, wenn deine Version ihn anbietet. Notiere den Ausgangswert.

Übernimm die Änderung, schließe das Fenster und starte denselben Befehl erneut. Die Einstellung sollte im Testprefix erhalten sein. Setze sie anschließend wieder auf den notierten Wert. Dein anderer Prefix erhält dadurch nicht dieselbe Einstellung.

Die ausgewählte Windows-Version ist eine Kompatibilitätsvorgabe, keine Installation dieser Windows-Version. Auch eine DLL-Überschreibung ist eine gezielte Entscheidung, kein pauschaler Beschleuniger. Baue nicht gleichzeitig mehrere Runtime-Pakete und Overrides ein, wenn du einen Fehler eingrenzen willst.

Die Dateien ansehen und Laufwerkszuordnungen verstehen

Nach dem ersten Start kannst du die zwei typischen Verzeichnisse ansehen:

ls -ld ~/wine-tutorial/drive_c ~/wine-tutorial/dosdevices

Unter drive_c liegen virtuelle Windows-Verzeichnisse. dosdevices kann zusätzlich Verweise auf Teile deines echten Linux-Dateisystems enthalten. Ein sichtbares Windows-Laufwerk ist deshalb nicht zwingend ein vollständig abgetrennter Speicherbereich.

Genau daraus folgt eine wichtige Grenze: Ein eigenes Prefix ist keine Sicherheits-Sandbox. Ein darin gestartetes schädliches Programm kann im Rahmen deiner Benutzerrechte Dateien erreichen. Verwende vertrauenswürdige Programme; für bewusst untersuchte unbekannte Software braucht es ein anderes Isolationskonzept.

Architektur und Dateisystem nicht blind ändern

Die Prefix-Architektur wird beim Anlegen festgelegt. Ein vorhandenes Prefix wird nicht durch eine spätere WINEARCH-Variable einfach zwischen 32 und 64 Bit umgewandelt. Welche Varianten deine Wine-Pakete unterstützen, hängt auch vom verwendeten WoW64-Aufbau ab.

Für den ersten Test lassen wir den Paketstandard gelten. Falls ein Spiel ausdrücklich eine bestimmte Architektur braucht, richte dafür eine eigene, passende Umgebung nach dessen aktuellem Installer beziehungsweise Runner ein. Übertrage ältere win32-Anleitungen nicht ungeprüft auf jedes moderne Wine-Paket.

Ein Prefix braucht passende Dateisystemeigenschaften und Rechte. Probleme auf zusätzlich eingebundenen Laufwerken können von Mounts, Groß-/Kleinschreibung oder Links stammen. Mein Laufwerksartikel erklärt die darunterliegende Ebene.

Einen Prefix sichern und einen Fehler untersuchen

Schließe zunächst alle Programme dieser Umgebung. Warte bei Bedarf, bis ihre Wine-Prozesse beendet sind:

env WINEPREFIX="$HOME/wine-tutorial" wineserver --wait

Der Befehl wartet; er beendet kein noch offenes Spiel für dich. Sichere danach den ganzen Prefix in ein neues, bislang unbenutztes Ziel. Wichtige Spielstände können außerdem außerhalb des Prefix liegen oder über einen Launcher synchronisiert werden; prüfe ihre tatsächlichen Speicherorte.

Für eine Diagnose notierst du Prefixpfad, Runner-Version, Startbefehl und letzte Änderung. Eine Konsolenzeile mit fixme ist noch kein Beweis für die Absturzursache. Vergleiche das Verhalten vor und nach einer Änderung und lies die relevante Ausgabe im Umfeld des Fehlers.

Lutris und der Rückweg zur normalen Umgebung

In Lutris prüfst du den für das Spiel eingetragenen Prefixpfad und Runner. Änderst du sie, notiere vorher die alten Werte und sichere wichtige Daten. Eine zusätzliche Testinstallation verdient einen eigenen Spiel-/Prefixeintrag, damit das vorhandene Spiel nachvollziehbar bleibt.

Nach der Übung schließt du winecfg; ein normaler Wine-Aufruf ohne unsere env-Auswahl verwendet wieder seine normale Umgebung. Behalte den Testordner zunächst, wenn du etwas daraus brauchst. Entferne ihn erst nach Prüfung seines Inhalts und ohne pauschale Löschbefehle für sämtliche Prefixe.
