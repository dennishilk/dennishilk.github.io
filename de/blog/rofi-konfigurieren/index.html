Rofi & Desktop

Rofi konfigurieren: App-Launcher, Tastenkürzel und Themes

Von Dennis Hilk8. Oktober 20265 Minuten Lesezeit
Programmauswahl auf deinem Rechner

Ein schneller Programmstarter spart auf einem Tastatur-Desktop viele Umwege. Du öffnest Rofi, tippst einen Teil des Namens und bestätigst mit Enter. Mein Gruvnode-Profil auf dem X1 Carbon nutzt dafür einen kompakten Launcher in dunklen Gruvbox-Farben.

Hier erkläre ich die veröffentlichte Rofi-Datei und eine eigene kleine Testkonfiguration. Voraussetzung ist ein installiertes Rofi in einer passenden grafischen Sitzung. Mein konkreter Bezug ist XMonad unter X11; bei Wayland musst du die Unterstützung deiner installierten Rofi-Version prüfen.

drun und run haben unterschiedliche Aufgaben

drun zeigt Anwendungen aus Desktop-Dateien, also typischerweise dieselben Programme, die ein Desktop-Menü kennt. Dort können ein verständlicher Anzeigename, ein Icon und der Startbefehl hinterlegt sein. run orientiert sich an ausführbaren Befehlen, beispielsweise aus deinem PATH.

Für Einsteiger ist drun ein guter Start: Du suchst nach dem Programmnamen, statt einen vollständigen Befehl zu kennen. Dass ein Programm im run-Modus erreichbar ist, bedeutet noch nicht, dass eine passende Desktop-Datei für drun existiert. Bei Flatpak oder selbstgebauten Apps ist das ein häufiger Unterschied.

Teste zunächst ohne eigenes Theme:

rofi -show drun

Tippe einen Namen, bewege die Auswahl mit den Pfeiltasten und starte mit Enter. Escape schließt das Fenster ohne Start.

Meine Rasi-Datei lesen

Rasi ist Rofis Konfigurations- und Theme-Syntax. Der obere Teil meiner Datei beschreibt Verhalten:

configuration {
    modi: "drun,run";
    show-icons: true;
    display-drun: "Apps";
    font: "JetBrains Mono 11";
    drun-display-format: "{name}";
}

modi legt die angebotenen Modi fest; -show drun wählt beim Aufruf den Startmodus. show-icons erlaubt Icons, installiert aber kein Icon-Theme. display-drun setzt die Beschriftung und drun-display-format begrenzt die dargestellten Informationen auf den Namen.

Im Theme-Teil werden Widgets wie window, inputbar, listview und element selected gestaltet. Globale Farbwerte liegen bei mir im *-Block. Ein Verweis wie @foreground benutzt einen solchen Wert an anderer Stelle. So kannst du eine Farbe ändern, ohne jeden einzelnen Texteingang zu bearbeiten.

Eine eigene kleine Testdatei erstellen

Lege einen separaten Ordner an:

mkdir -p ~/rofi-tutorial

Speichere diese vollständige Übungsdatei als ~/rofi-tutorial/config.rasi. Sie ist bewusst ein eigenes Beispiel und kein vollständiger Ersatz für mein Theme:

configuration {
    modi: "drun,run";
    show-icons: false;
    font: "monospace 12";
}
* {
    background-color: #1d2021;
    text-color: #ebdbb2;
}
window {
    width: 40%;
    padding: 16px;
}
listview {
    lines: 6;
}
element selected {
    background-color: #504945;
    text-color: #b8bb26;
}

Starte ausschließlich diese Datei:

rofi -config ~/rofi-tutorial/config.rasi -show drun

Erwartet werden ein dunkles Fenster, sechs sichtbare Listenzeilen und eine anders gefärbte Auswahl. Die reguläre ~/.config/rofi/config.rasi bleibt erhalten. Escape beendet die Übung; ein Aufruf ohne -config verwendet wieder die normale Konfiguration.

Größe, Abstände und Auswahl verändern

Mein Original verwendet width: 38%, zwölf Pixel Fensterabstand und acht Listenzeilen. Das sind Gestaltungsentscheidungen für meinen Bildschirm. Auf einem kleinen Display kann eine prozentuale Breite sinnvoll sein, während eine lange App-Bezeichnung zusätzlichen Platz benötigt.

Ändere in der Testdatei jeweils einen Wert: zuerst lines, danach width. Starte Rofi nach jeder Änderung erneut. Du erkennst dadurch, welche Einstellung verantwortlich ist. Das vermeidet die typische Situation, in der zugleich Schrift, Fenster und Farben geändert werden und der eigentliche Fehler verborgen bleibt.

Rasi benötigt Semikolons nach Eigenschaften und passende Klammern. Ein Farbwert wie #b8bb26 enthält keine Anführungszeichen. Strings wie "drun,run" dagegen schon. Wenn Rofi einen Fehler meldet, beginnt die Prüfung an der genannten Zeile und an der Eigenschaft unmittelbar davor.

Rofi mit einem XMonad-Tastenkürzel öffnen

Auf meinem X1 startet Super + D den Launcher. Der Window Manager führt dabei im Kern rofi -show drun aus. Das globale Tastenkürzel gehört also in die XMonad-Konfiguration, während Farben und Fenstergröße in Rasi bleiben.

Ein Ausschnitt für eine bestehende, mit EZConfig eingerichtete Tastenkürzelliste sieht so aus:

("M-d", spawn "rofi -show drun")

Das ist kein vollständiges xmonad.hs. Lies den XMonad-Einstieg, bevor du den Eintrag an der richtigen Stelle ergänzt. Prüfe außerdem, ob M-d bereits belegt ist. Ein funktionierender Terminalaufruf von Rofi sollte dem Einbau eines Tastenkürzels vorausgehen.

Wenn ein Programm oder ein Icon fehlt

Beobachtung Nächster sinnvoller Check
App fehlt in drun Desktop-Datei und App-Installation prüfen
Befehl fehlt in run PATH und ausführbare Datei prüfen
Icons fehlen Erst mit show-icons: false testen, dann Icon-Theme prüfen
Schrift passt nicht Tatsächlich installierten Familiennamen verwenden
Hotkey funktioniert nicht Befehl im Terminal testen, danach XMonad-Belegung prüfen

Rofi installiert die ausgewählte Anwendung nicht. Es startet, was auf deinem Rechner eingerichtet ist. Ebenso macht ein schönes Theme einen fehlerhaften Startbefehl nicht korrekt. Trenne deshalb Darstellung, App-Eintrag und Window-Manager-Tastenkürzel.

Lokale Auswahl und gestartete Anwendungen

Die gezeigte Auswahl braucht keinen Cloud-Account. Ein anschließend gestarteter Browser oder Spielelauncher kann selbstverständlich online gehen. Rofi kann außerdem eigene Modi und Skripte ausführen; deren Verhalten hängt vom jeweiligen Code ab. Übernimm Skripte erst, nachdem du ihre Eingaben, Dateizugriffe und Befehle verstanden hast.
