    Dual Boot: eine SSD oder zwei?

    Dual Boot bedeutet: Windows und Linux sind direkt auf der Hardware installiert, und beim Start entscheidest du, welches Betriebssystem läuft. Keine Virtualisierung, kein WSL. Wer Windows noch für Spiele, Programme oder einzelne Geräte braucht, kann Linux so ohne einen endgültigen Schnitt kennenlernen. Das größte Risiko ist nicht Linux selbst, sondern die falsche Auswahl beim Partitionieren.

    Eine SSDWindows 11 + DatenLinux /Gemeinsamer Speicher und eventuell gemeinsame EFI-Partition
    Zwei SSDsSSD 1 · WindowsSSD 2 · LinuxEinfacher zu trennen, aber EFI-Abhängigkeit prüfen

    Der Assistent oben läuft lokal im Browser, liest keine Laufwerke aus und führt keine Änderungen aus. Er ersetzt weder ein Backup noch die Sichtprüfung des Installationsbildschirms.

    Vorbereitung unter Windows 11

    1. Backup prüfen: Fotos, Dokumente, Browserdaten, Schlüssel und Spielstände auf einem externen Datenträger sichern. Einige Dateien testweise öffnen. Ein vollständiges Systemabbild ist hilfreich.
    2. Windows-Wiederherstellungsmedium: Vorher einen funktionierenden Wiederherstellungs-/Installationsstick bereitstellen.
    3. UEFI nachsehen: Win+R → msinfo32. Unter „BIOS-Modus“ sollte bei Windows 11 normalerweise UEFI stehen. Der Linux-USB muss im selben Modus gestartet werden.
    4. Datenträger erkennen: Win+X → Datenträgerverwaltung. Modell, Kapazität, C:-Größe, EFI- und Recovery-Partition notieren oder fotografieren. Die Nummerierung kann sich unter Linux ändern.
    5. BitLocker/Geräteverschlüsselung: Status in Windows prüfen und Wiederherstellungsschlüssel sichern. Bei Installation auf derselben SSD kann aktives BitLocker ein geführtes „neben Windows“ verhindern: Schutz aussetzen entschlüsselt das Laufwerk nicht. Zuerst die offiziellen Hinweise lesen.
    6. Schnellstart: Windows-Schnellstart in Systemsteuerung → Energieoptionen → Verhalten des Netzschalters deaktivieren, besonders wenn Linux auf NTFS zugreifen soll. Windows vollständig herunterfahren, nicht aus einem Ruhezustand heraus partitionieren.
    7. Eine SSD: Unter Windows mit Rechtsklick auf C: → „Volume verkleinern“ etwa 80–120 GB nicht zugeordneten Speicher für einen bequemen Einstieg freigeben. Große Spiele brauchen erheblich mehr. Diesen Bereich nicht als NTFS formatieren.
    8. Zwei SSDs: Die Linux-Ziel-SSD anhand von Modell und Kapazität identifizieren. Eine getrennte SSD garantiert nicht, dass der Installer auch eine getrennte EFI-Partition benutzt.
    Wichtig: EFI-Systempartition, MSR und Windows-Recovery nicht löschen oder formatieren. Falls die SSD im Linux-Installer fehlt, Intel RST/VMD/RAID nicht blind auf AHCI umstellen – Windows kann danach nicht mehr starten.

    Installationsstick erstellen und Linux testen

    1. Die ISO ausschließlich von der offiziellen Distributionsseite laden und nach Möglichkeit die SHA256-Prüfsumme kontrollieren.
    2. Mit Rufus oder balenaEtcher einen USB-Stick (8 GB oder größer) schreiben. Dabei werden die Daten auf dem USB-Stick gelöscht.
    3. Beim Einschalten das einmalige Bootmenü öffnen (oft F12, F11, Esc oder F8). Den Eintrag mit UEFI für den Stick wählen.
    4. Die Live-Sitzung ausprobieren: WLAN, Monitor, Touchpad, Ton, Grafik und Tastatur testen. Erst danach installieren.
    5. Wenn Secure Boot blockiert: nicht einfach Schlüssel löschen. Distributionshilfe lesen, BitLocker-Recovery-Key sichern und Änderungen nachvollziehbar dokumentieren.

    Linux installieren: die Unterschiede der Distributionen

    Linux Mint, Ubuntu und Zorin OS

    Diese Installer führen Anfänger in der Regel grafisch durch die Installation. Bei nur einer SSD die Option „neben Windows installieren“ ausschließlich wählen, wenn das korrekte Laufwerk und der erwartete freie Bereich angezeigt werden. Wenn das wegen BitLocker nicht möglich ist, niemals ersatzweise „Datenträger löschen“ wählen. Bei einer zweiten SSD die korrekte Zielplatte auswählen und die Frage nach dem EFI-Bootpfad beachten. Beschriftungen können zwischen Versionen abweichen.

    Debian, Fedora und openSUSE

    Auch hier gibt es geführte oder grafische Partitionswerkzeuge. Entscheidend ist stets: nur den vorbereiteten freien Bereich beziehungsweise die eindeutig identifizierte zweite SSD benutzen. „Gesamten Datenträger verwenden“ löscht normalerweise die Partitionen des gewählten Datenträgers. Wer manuell partitioniert, muss EFI-Systempartition, Root-Mountpunkt und Dateisysteme verstehen.

    Arch Linux und CachyOS

    Arch ist ein anderer Schwierigkeitsgrad. archinstall kann die Einrichtung erleichtern, nimmt dir aber nicht ab zu wissen, welche EFI- und Windows-Partition unbedingt erhalten bleiben müssen. Eine bereits benutzte Windows-EFI-Systempartition darf beim Dual Boot nicht formatiert werden. Der benötigte Mountpunkt hängt vom Bootloader ab; Windows erzeugt mitunter eine für mehrere Linux-Kernel zu kleine EFI-Partition. Arch Installationsanleitung und Dual-Boot-Wiki sind Pflichtlektüre. CachyOS hat einen grafischen Installer, aber dieselben grundlegenden Sicherheitsregeln gelten.

    Vor dem endgültigen Bestätigen: Datenträgermodell, Größe, zu löschende/zu formatierende Partitionen und den vollständigen Änderungsüberblick lesen. Ist irgendetwas unklar, abbrechen und nachprüfen.

    Nach der Installation beide Systeme prüfen

    1. Installationsstick entfernen und Linux starten.
    2. Im Terminal mit lsblk -f und findmnt / rein lesend kontrollieren, welches Dateisystem aktiv ist.
    3. Windows über Windows Boot Manager oder das Bootmenü starten und Daten, Uhrzeit sowie BitLocker-Status prüfen.
    4. Danach Linux erneut starten. Wenn Windows im Linux-Bootmenü fehlt, bedeutet das nicht automatisch Datenverlust: oft bleibt es separat im UEFI-Bootmenü verfügbar.
    5. Bei zwei SSDs nur bei ausgeschaltetem und vom Strom getrenntem Gerät testen, ob Linux ohne Windows-SSD startet. Falls nicht: Bootpfad hängt möglicherweise von der Windows-EFI-Partition ab.
    6. Backup und Windows-Recovery-Medium sicher aufbewahren.

    Linux wieder entfernen und Windows behalten

    Erst Windows unabhängig starten, dann Linux entfernen. Wähle im UEFI-Bootmenü „Windows Boot Manager“ und prüfe, ob Windows mehrfach ohne Linux-Bootloader startet. Sichere alle Linux-Daten. Anschließend mit dem dokumentierten Partitionsplan nur eindeutig zugeordnete Linux-Partitionen entfernen. Die EFI-Systempartition niemals pauschal löschen: Sie kann für Windows notwendig sein. Das Vergrößern von C: klappt nicht immer direkt, wenn Partitionen dazwischenliegen. Wenn Windows nicht allein startet, zuerst mit Windows-Reparaturmedium und automatischer Starthilfe den Start reparieren; keine blind übernommenen diskpart-Befehle verwenden. Erst nach erfolgreichen Neustarts veraltete Bootmenü-Einträge entfernen.

    Windows sicher entfernen und Linux behalten

    Dieser Weg braucht mehr Vorsicht, wenn sich Linux und Windows eine EFI-Systempartition teilen. Sichern: eigene Dateien beider Systeme, Lizenz-/Recovery-Daten und Linux-Konfiguration. Unter Linux mit lsblk -f, findmnt / und (falls vorhanden) efibootmgr -v erst einmal nur auslesen, welche SSD und EFI-Partition Linux braucht. Linux muss ohne Windows-Partitionen zuverlässig bootfähig sein, bevor du Windows-NTFS-, MSR- oder Recovery-Partitionen löscht. Eine geteilte EFI-Partition muss gegebenenfalls erhalten bleiben oder Linux bekommt zuerst einen getesteten neuen EFI-Bootpfad. Wenn du nicht sicher bist, welche Partition wozu gehört: nicht löschen.

    Erst Windows oder erst Linux installieren?

    Mein Grundsatz war immer: erst Windows, dann Linux. Genau das rät auch Linux Mint. Windows legt seine Bootdateien an und nimmt gern den bevorzugten Startplatz ein. Bei UEFI bedeutet das oft nur eine Änderung der Bootreihenfolge – die Linux-Partition ist nicht zwingend überschrieben. Arch Linux lässt sich laut ArchWiki auch vor Windows installieren, nur werden die Reparaturwege komplizierter. Für Einsteiger ist die Reihenfolge Windows zuerst, Linux danach deshalb besser.

    Meine alte Dual-Boot-Geschichte: Die falsche Windows-Uhr

    Und dann war da noch meine Dual-Boot-Uhr. 😄 Früher war nach dem Wechsel von Linux zurück nach Windows immer die Uhr falsch. Das kommt von der RTC-Hardware-Uhr: Linux interpretiert sie meist als UTC, Windows normalerweise als Ortszeit. Je nach Jahreszeit ergibt das eine Verschiebung von ein oder zwei Stunden; manche Distributionen berücksichtigen Windows bereits bei der Installation.

    Mit timedatectl siehst du unter Linux die Einstellungen. Das ArchWiki empfiehlt, Windows ebenfalls auf UTC umzustellen. Dazu nach einer Sicherung und Prüfung der Registry-Einstellung eine Windows-Eingabeaufforderung als Administrator öffnen:

    reg add "HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /d 1 /t REG_DWORD /f

    Danach vollständig neu starten, Zeitzone und Synchronisierung prüfen. Auf verwalteten Rechnern solche Registry-Änderungen nur mit Zustimmung der Administration vornehmen. Linux auf lokale RTC umzustellen ist eine Alternative, kann laut ArchWiki aber Sommerzeit- und Synchronisierungsprobleme verursachen.

    Fehler und Lösungen

    Linux erkennt meine SSD nicht

    Herstellerhinweise zu Intel RST/VMD, Treibern und BIOS lesen. Controller-Modus nicht unvorbereitet ändern, sonst startet Windows eventuell nicht mehr.

    „Neben Windows installieren“ fehlt

    BitLocker/Geräteverschlüsselung, freien nicht zugeordneten Speicher und UEFI-Bootmodus prüfen. Bei Unsicherheit abbrechen statt Windows zu überschreiben.

    Nach einem Windows-Update startet nur noch Windows

    UEFI-Bootmenü öffnen. Oft wurde nur Windows Boot Manager nach oben gesetzt. Linux ist nicht automatisch gelöscht.

    GRUB zeigt Windows nicht an

    Windows Boot Manager direkt im UEFI-Menü prüfen. Der fehlende Menüeintrag sagt nichts darüber aus, ob Windows noch vorhanden ist.

    BitLocker verlangt einen Wiederherstellungsschlüssel

    Firmware nicht wiederholt auf Verdacht umstellen; gesicherten Schlüssel verwenden. TPM-/Secure-Boot-Änderungen können Recovery auslösen.

    C: lässt sich kaum verkleinern

    Backup prüfen, Speicherbereinigung und Windows-Optimierung kontrollieren. Recovery-Partitionen nicht blind verschieben. Gegebenenfalls zweite SSD wählen.

    Häufig gestellte Fragen

    Kann ich Linux erst ohne Installation testen?

    Ja. Live-USB oder virtuelle Maschine sind der sicherste Einstieg, wenn man nur ausprobieren möchte.

    Muss Secure Boot aus sein?

    Nein. Mint, Ubuntu, Fedora und andere haben signierte Bootpfade. Es hängt von der Distribution und deinem Setup ab. Änderungen können BitLocker-Recovery auslösen.

    Sind zwei SSDs automatisch vollständig getrennt?

    Nein. Linux kann trotzdem die EFI-Partition der Windows-SSD nutzen. Unabhängigkeit durch einen Teststart ohne die andere SSD prüfen.

    Wie viel Speicher braucht Linux?

    80–120 GB sind für einen Desktop ein komfortabler Startwert; große Steam-Spiele brauchen deutlich mehr.

    Was zuerst neu installieren – Windows oder Linux?

    Windows zuerst, Linux danach ist die einfachere, offiziell empfohlene Reihenfolge für Einsteiger.

    Wie werde ich Windows später wieder los?

    Linux erst unabhängig bootfähig machen und testen, Daten sichern, danach nur die eindeutig zugeordneten Windows-Partitionen entfernen. Gemeinsame EFI nicht blind löschen.
