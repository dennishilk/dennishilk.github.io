BoringOS

An independent experimental desktop operating system built from scratch — not Linux, not BSD and not a wrapper around another kernel. BoringOS now has its own kernel, Ring3 userspace, persistent BoringFS root, display service, native tiling BoringWM, graphical terminal, editor and file manager, real hardware inventory and a growing BoringOS-owned xHCI/USB stack.boring is not a bug. it's the entire operating system now.

02 · Architecture

A small native stack that is actually ours.

The kernel provides bounded primitives; desktop policy remains in Ring3. There is no X11 or Wayland underneath BoringWM.

03 · Modern USB path

xHCI now delivers real HID reports.

M48–M52 progressed from PCI controller discovery to actual controller-completed keyboard and tablet report DMA. No fake input is inserted at the decoder boundary.

M48xHCI controllerBAR/MMIO validation, ownership handoff, rings, ports and bounded HID report decoders.
M49Address devicesRoot-port reset, Enable Slot, Address Device and per-device contexts.
M50–51Descriptors + endpointsEP0 GET_DESCRIPTOR, SET_CONFIGURATION and descriptor-derived Interrupt-IN endpoint setup.
M52Real reportsNormal TRBs, DMA buffers, Transfer Events, keyboard/tablet decode and bounded re-arm.

Deliberate boundary: no hub support, no USB mass storage, and USB reports are not yet fed into the normal desktop input queue. That integration belongs to M53.

05 · Current limits

Unsupported still means unsupported.

BoringOS deliberately separates hardware detection from hardware support.

Graphics

Firmware/Limine framebuffer + software composition. No native AMD/NVIDIA/Intel GPU acceleration yet.

Storage

VirtIO + BoringFS is the verified persistent root. AHCI and NVMe are not implemented yet.

Connectivity

No networking or audio stack yet. No browser claim, no YouTube claim.

Physical PCs

Readiness work exists, but QEMU remains the verified platform. A physical-hardware success claim comes only after a real boot.
