BoringOS

An independent experimental desktop operating system built from scratch — not Linux, not BSD and not a wrapper around another kernel. BoringOS now has its own kernel, Ring3 userspace, persistent BoringFS root, display service, native tiling BoringWM, graphical terminal, editor and file manager, real hardware inventory, a BoringOS-owned xHCI USB input path and a native AHCI/SATA storage path.boring is not a bug. it's the entire operating system now.

03 · Native USB input

xHCI now drives the desktop without i8042.

M48–M54 progressed from controller discovery to a complete USB-only graphical desktop path. Keyboard and tablet reports travel through real xHCI Transfer Events into the existing canonical input queue and Ring3 desktop services.

M48–49Controller + devicesBAR/MMIO validation, ownership, rings, root-port handling, Enable Slot and Address Device.
M50–52Descriptors + reportsEP0 control transfers, configuration, HID endpoints and real Interrupt-IN report DMA.
M53Canonical inputReal USB keyboard/tablet reports feed the existing source-independent BoringOS input queue.
M54USB-only desktopq35 with i8042=off: cursor, buttons and Super+Return launch the real graphical terminal.

Deliberate boundary: no USB hubs or USB mass storage yet. The focused M54/M57 desktop proof uses xHCI keyboard and tablet as the real input path, with no PS/2 fallback.

04 · Native SATA path

AHCI now carries the persistent BoringFS root.

M55–M57 extended the existing generic block-device architecture instead of creating a second storage stack: real AHCI controller discovery, synchronous DMA reads and writes, cache flush and a persistent BoringFS root.

M55AHCI foundationPCI controller selection, real ABAR/MMIO, CAP/PI inspection and bounded SATA port/device discovery.
M56Read-only block pathIDENTIFY DEVICE, real geometry, bounded PRDT DMA reads and read-only sata0 through the M21 block API.
M57Writes + flushReal WRITE DMA/WRITE DMA EXT completions, capability-correct FLUSH CACHE and strict LBA/PRDT bounds.
M57Persistent rootBoringFS root over AHCI without a VirtIO root; /persist verified host-side and again after reboot.

The focused M57 proof combines the AHCI-backed root with the USB-only desktop on the same q35 machine. QEMU remains the verified hardware platform; this is not yet a general physical-PC success claim.

06 · Current limits

Unsupported still means unsupported.

BoringOS deliberately separates hardware detection from hardware support.

Graphics

Firmware/Limine framebuffer + software composition. No native AMD/NVIDIA/Intel GPU acceleration yet.

Storage

Persistent BoringFS roots are verified through VirtIO and native AHCI in QEMU. No NVMe or general partition layer yet.

Connectivity

No networking or audio stack yet. No browser claim, no YouTube claim.

Physical PCs

Readiness work exists, but QEMU remains the verified platform. A physical-hardware success claim comes only after a real boot.
