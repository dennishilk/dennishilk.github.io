    Dual boot: one SSD or two?

    Dual boot means Windows and Linux are installed directly on your PC, and you choose which to start. No virtual machine or WSL. It is useful when you still need Windows for games, applications or hardware. The greatest risk is selecting the wrong partition, not trying Linux itself.

    The interactive guide above runs locally in your browser. It cannot inspect your disks or execute commands. You must verify every action on your PC.

    Prepare Windows 11 safely

    1. Verify a backup: save pictures, documents, browser data, recovery keys and game saves externally. Open some saved files to verify. A full disk image is useful.
    2. Windows recovery: prepare working Windows 11 installation/recovery media before starting.
    3. Check firmware: Win+R → msinfo32. Windows 11 should normally say UEFI under BIOS Mode. Boot the Linux USB in the same mode.
    4. Identify drives: Win+X → Disk Management. Record models, capacities, C: size, EFI and recovery partitions. Drive numbering may change under Linux.
    5. BitLocker/Device Encryption: check the setting and save the recovery key. On a shared drive, active encryption may prevent safe guided installation alongside Windows. Suspending BitLocker is not the same as decrypting. Read the official Ubuntu guidance first.
    6. Fast Startup: disable it in Control Panel → Power Options → Choose what the power buttons do, especially before sharing NTFS files. Shut Windows down fully, never resize a hibernated volume.
    7. One SSD: right-click C: in Disk Management → Shrink Volume. Leave perhaps 80–120 GB of unallocated space for a comfortable desktop (large games need more). Do not format this new space as NTFS.
    8. Two SSDs: identify the Linux target by model and capacity. Separate hardware does not guarantee a separate EFI boot path.
    Important: Do not format or delete EFI, Microsoft Reserved or Windows Recovery partitions. If Linux cannot see the SSD, do not blindly change Intel RST/VMD/RAID to AHCI: Windows might fail to boot.

    Create a bootable Linux USB and test

    1. Download an ISO exclusively from the distribution's official website and verify its SHA256 checksum when possible.
    2. Use Rufus or balenaEtcher to write a USB stick (8 GB or larger). Imaging erases the USB stick's existing data.
    3. Open the one-time boot menu (often F12, F11, Esc or F8) and choose the USB entry labeled UEFI.
    4. Before installing, test the live environment: Wi-Fi, display, keyboard, audio, trackpad and graphics.
    5. If Secure Boot prevents startup, do not casually erase keys. Read distro documentation and save the BitLocker recovery key before firmware changes.

    Installing Linux: differences by distribution

    Linux Mint, Ubuntu and Zorin OS

    These installers provide a graphical route suited to beginners. With one SSD, choose install alongside Windows only if it correctly identifies the drive and intended free space. If BitLocker prevents this, never substitute “erase disk”. With two SSDs, explicitly choose the Linux target and consider where its EFI files will go. Exact installer labels vary.

    Debian, Fedora and openSUSE

    These offer guided or graphical disk setup. Use the verified unallocated space or your explicitly chosen second SSD. “Use entire disk” usually means all partitions on the chosen drive. Manual partitioning requires understanding EFI, root mount points and filesystem types.

    Arch Linux and CachyOS

    Arch is more demanding. archinstall reduces typing but cannot tell which personal data to preserve. Never format an existing Windows EFI partition in a shared dual-boot setup. Its mount point depends on the bootloader, and the small EFI partition created by Windows may need special planning. Read the Arch installation guide and dual-boot wiki. CachyOS provides a graphical installer but shares the same underlying disk/EFI constraints.

    Before confirming changes: read the drive model, size, full list of partitions to format or delete, and the installation summary. If anything is unclear, stop and verify.

    After installation: verify both operating systems

    1. Remove the installation USB and start Linux.
    2. Use read-only lsblk -f and findmnt / to check active filesystems.
    3. Start Windows via Windows Boot Manager or UEFI menu. Check files, clock and BitLocker status.
    4. Boot Linux again. If Windows is missing from the Linux boot menu, it may still be present in the UEFI boot menu.
    5. With two SSDs, only when fully powered off and disconnected from electricity, check whether Linux starts without the Windows SSD. Failure suggests an EFI boot dependency.
    6. Store recovery media and backups safely.

    Remove Linux while keeping Windows

    First verify Windows boots independently, then remove Linux. Select Windows Boot Manager directly in UEFI and confirm repeated successful starts. Back up Linux data. Use your documented disk layout to remove only positively identified Linux partitions. Never blindly erase the EFI System Partition: it may contain the Windows boot files. Extending C: is not always straightforward if recovery partitions intervene. If Windows fails to boot, use Windows recovery media and try automated Startup Repair first. Avoid copying arbitrary diskpart commands. Clean up obsolete boot entries only after Windows works consistently.

    Remove Windows while keeping Linux

    Be particularly careful if Linux uses the Windows EFI System Partition. Back up data and Windows recovery details. Under Linux, use read-only lsblk -f, findmnt / and (where available) efibootmgr -v to map your filesystems and EFI boot paths. Linux must boot independently before deleting Windows NTFS, MSR or recovery partitions. A shared EFI partition may have to remain, or you must create and test an independent Linux EFI path first. If you cannot identify a partition with confidence, do not delete it.

    Install Windows first, or Linux first?

    My rule has always been: Windows first, then Linux. Linux Mint recommends the same. Windows sets up its boot files and may take the top UEFI boot priority. With UEFI this often means a changed boot order, not an erased Linux partition. The ArchWiki documents installing Windows second as possible, but it adds complexity. For beginners, Windows first remains simpler.

    My old dual-boot mystery: the wrong Windows clock

    When I dual-booted, it seemed to happen every time: boot Linux, go back to Windows, and the clock was wrong again. 😄 The reason is the hardware real-time clock (RTC): Linux usually interprets it as UTC, Windows normally as local time. That can shift the clock by one or two hours. Some installers handle this automatically.

    In Linux run timedatectl. The ArchWiki recommends making Windows use UTC too. After backing up and checking the existing Registry value, open Windows Command Prompt as Administrator:

    reg add "HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /d 1 /t REG_DWORD /f

    Fully reboot and check time zone and synchronization. On managed PCs, get administrator approval before registry changes. Making Linux use localtime is possible but may cause daylight-saving or synchronization problems.

    Common errors and fixes

    Linux doesn't see my SSD

    Consult manufacturer instructions for Intel RST/VMD and drivers. Do not switch storage-controller modes blindly; Windows may stop booting.

    Install alongside Windows is missing

    Check BitLocker/Device Encryption, unallocated space and UEFI mode. Do not overwrite Windows if unsure.

    Windows boots after an update, Linux seems gone

    Check the UEFI boot menu. Windows may have changed boot priority without deleting Linux.

    GRUB doesn't show Windows

    Look for Windows Boot Manager in firmware. No GRUB entry does not prove Windows is gone.

    BitLocker requests a recovery key

    Do not keep changing firmware settings on a guess. Use the saved key. TPM and Secure Boot changes can trigger recovery.

    Can't shrink C: enough

    Verify your backup, use Windows cleanup/optimization tools, and don't move recovery partitions blindly. A second SSD may be easier.

    Frequently asked questions

    Can I test Linux without installing it?

    Yes. A live USB or a virtual machine is a safe way to try Linux first.

    Must Secure Boot be off?

    No. Mint, Ubuntu, Fedora and others support signed boot paths. It depends on your distribution and configuration. Changes can trigger BitLocker recovery.

    Are two SSDs automatically independent?

    No. Linux may still use the Windows SSD's EFI partition. Verify with independent boot testing.

    How much space should Linux get?

    80–120 GB is comfortable for a desktop; large games need more.

    Install Windows or Linux first?

    Windows first and then Linux is the simpler, officially recommended order for beginners.

    How do I remove Windows later?

    Make Linux independently bootable first, verify and back up. Delete only verified Windows partitions, preserving shared EFI boot files.
