# USB, audio, input and virtual-hardware research

Actual editorial/source review: 2026-10-10. Linux source snapshot: `3857c2fe5449541e24afc5efdb0f81a8a8f9a3a0`.

This bounded group contains **38 profiles**: 10 usb, 10 audio, 8 input, 10 virtual. **21 profiles have exact curated PCI/USB pairs**; 17 are explicit generic class, protocol, codec or transport profiles. No hardware execution, minimum supported kernel release, distro-package recommendation or reproduced compatibility result is claimed.

## Verification method

Primary upstream bytes were retrieved over HTTPS from raw.githubusercontent.com at the immutable snapshot and read locally. Successful source locators were asserted against the retrieved files before writing this catalog. The web search/open service returned DisabledError for the attempted GitHub source open; direct primary-source retrieval supplied the actual evidence. No PCI/USB database was mass imported. The catalog stores the human-facing immutable GitHub URL, exact symbol/locator, checked claim and retrieval date for each reference. Numeric pairs were resolved from source symbols or literal device records, not inferred from market labels.

Module names in the catalog use the usual underscore spelling. Hyphenated object/source names and observed sysfs driver names can differ. Built-in drivers need not occur in lsmod or have a modinfo file. Candidate/source matching must remain distinct from pasted runtime binding.

## Structural distinctions and limits

- USB driver links belong to interfaces such as `1-2:1.0`; the parent device `1-2` cannot stand in for every composite function. Hub class can be advertised on a device or interface; UVC, audio, storage and input functions remain independently interpreted.
- USB storage class 08 does not establish UAS. Subclass, protocol, alternative interfaces, endpoint feasibility and actual binding matter. Neither generic mass-storage profile is a claimed bridge model.
- HDA controller PCI IDs and HDA codec IDs are separate namespaces. `0x10ec0892` is checked as an HDA codec identity and is deliberately not entered as PCI `10ec:0892`. Snapshot audio sources now live under `sound/hda/`; old `sound/pci/hda` paths were not used as evidence.
- The checked snapshot splits several HDA codec families into modules. ALC892 is under `snd_hda_codec_alc662`; HDMI has generic and vendor-specific modules. This is not a minimum-version statement and does not override observed installed-kernel names.
- Modern virtio PCI IDs are derived explicitly from `device - 0x1040`, the checked `VIRTIO_ID_*` constants and vendor 1af4. Transitional devices use subsystem-device IDs instead. Every included exact virtio PCI pair is modern; no guessed transitional pair is included.
- A PCI `virtio-pci` transport binding and a virtio child function driver are separate successful observations. Transport-only `virtio_pci` is deliberately excluded from every virtual profile’s module matching hints; its presence must not select all ten function profiles. Network, console, RNG, balloon, SCSI, 9P, GPU, input, vsock and audio perform different jobs; none identifies physical host hardware.
- The virtio-blk profile is intentionally owned by the network/storage research group and omitted here. The virtual group includes vsock instead; vsock does not imply an Ethernet/IP interface or a VMware hypervisor merely because the module begins with `vmw_`.
- Every checkpoint is a read-only query/listing. No serial channel is opened, random stream consumed, keystroke/event capture performed, rumble command sent, filesystem mounted, driver loaded/unbound, kernel parameter changed or firmware installed.
- Optional tools (pciutils, usbutils, alsa-utils, util-linux, iproute2 and kmod) may not be installed. Read access is normally unprivileged; journal access may require locally authorized elevation. Missing procfs/sysfs metadata is lack of observation, not automatic proof of unsupported hardware.
- Firmware `none-documented` means no external filename established in the checked path, not absence of device-internal firmware. Generic device-dependent entries do not fabricate package names or firmware patterns; optional HDA patch loading is distinguished from mandatory firmware.
