# Linux Fix Lab — independent technical spot audit

Editorial audit date: 2026-10-09. This is a bounded documentation audit, not hardware reproduction, a security certification, or full verification of every article. Category authors were still writing during the audit. The auditor did not edit category files, push Git changes, or publish the site.

## Scope and method

Read the content contract and checked two complete entries in each category, including the German and English possible-cause, diagnostic interpretation, fix, precaution and recovery text. Browsed upstream/distribution references for technical details. Also inspected the diagnostic command inventory and literal pattern fixtures across category files; this wider inspection is not a full editorial review of those additional articles.

The final primary complete-entry sample contains **24 entries across all 12 categories**, out of 150 source entries. Additional reads and focused signature checks are listed separately below.

## Actionable findings

1. **AppArmor journal filter loses the literal quotes.** The original command used `-g "apparmor="DENIED""`, which the shell parses as the unquoted regex `apparmor=DENIED`. Real kernel records contain `apparmor="DENIED"`; the command consequently misses its intended events. [Ubuntu's documented examples](https://ubuntu.com/server/docs/how-to/security/apparmor/) confirm the format. **Corrected and rechecked:** the single-quoted `--grep='apparmor="DENIED"'` argument preserves the required double quotes.

2. **Xid 79 signature matches its own negative example.** The original requirements `NVRM: Xid` plus `79,` matched `...: 31, pid=979, GPU memory page fault` because the PID ends in `79,`. Confirmed by the literal matcher semantics specified in the contract, not inferred from GPU symptoms. **Corrected and rechecked:** the signature now requires the Xid field delimiter `): 79,`; its intended positive matches and its negative no longer matches.

3. **AMDGPU inventory omits symlinked firmware.** The original `find ... -type f` excluded firmware symlink objects and did not follow a symlink used as the selected starting directory. This could make generated/symlinked layouts appear to lack a blob. [Kernel firmware search paths](https://docs.kernel.org/driver-api/firmware/fw_search_path.html). **Corrected and rechecked:** the inventory now uses `find -L`; the existing exact-requested-path and initramfs qualifications remain necessary.

## Conclusions within this scope

No outstanding concrete technical defect was identified in this spot sample after the three corrections above. The sample generally separates observed failure signals from possible root causes. Selected fixes keep DMA isolation and repository authentication intact, avoid force-loading modules or ABI symlink hacks, and explain irreversible recovery operations such as snapshot deletion or filesystem repair. The Btrfs usage=0 approach, WirePlumber migration, NVIDIA preservation interface, and XFS forced-shutdown log wording have direct primary support. The Nix module-merge signature's two phrases are in one [upstream error string](https://github.com/NixOS/nixpkgs/blob/master/lib/options.nix), so it is compatible with line-based matching; it is not a multiline defect.

The final independent fixture scan covered **150 category entries, 163 positive pattern fixtures, 326 negative pattern fixtures and 325 diagnostic command argument parses**. All intended positives matched, no supplied negative matched, and all command strings parsed as shell arguments. The scan deliberately excluded `assistants.json`, `relations.json` and `generated-manifest.json`. Shell argument parsing checks syntax, not whether every utility exists on every distribution or whether every command's interpretation is correct. Tree, runtime, site-generation and browser checks remain the implementation owner's separate responsibility.

## Remaining limitations

- No diagnostic command was executed on Dennis's workstation. No fix was applied to a real affected system.
- The browser UI, deployment and all-page SEO work are outside this content audit.
- Literal positive/negative fixtures demonstrate parsing behavior only; unrecognized logs and changed upstream wording remain possible. A match is not a unique diagnosis.
- ArchWiki full-page fetches returned bot-check pages; the partial-upgrade and --sysroot points were checked using official indexed excerpts plus the independently fetched Arch pacman manual. Some long-source fetches or alternate mirrors failed; the audit does not claim to have independently verified every source URL or every log string.
- The 150-entry collection is substantially larger than the complete-entry audit sample. Do not describe all 150 articles or 300 localized pages as fully verified on the strength of this audit.
