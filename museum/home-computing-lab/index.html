How does a person learn to understand computers?

This is not a biography or a catalogue. It follows a changing relationship with machines: using them, questioning them, opening them, changing them, occasionally breaking them, learning why, and making them do something they were not originally intended to do.

Lab methodology

A recurring operating principle

  1. See a system.
  2. Ask how it works.
  3. Open it.
  4. Change it.
  5. Break something occasionally.
  6. Learn why.
  7. Make it do something it was not originally intended to do.

Personal computing path

Signal path: curiosity becomes a lab

01USE

First contact

MEMORY In the early 1990s, a second-hand Amiga 500 made the computer a fascinating machine to use and explore. Games such as The Secret of Monkey Island, Wings, Another World / Out of This World, Eye of the Beholder and Loom were part of that remembered encounter—not a checklist, but an invitation to curiosity.

USE → QUESTION

02QUESTION

Learning the machine

MEMORY A Schneider PC and the DOS era made software feel physical: many sequential floppy disks, time, and attention. A remembered Quake installation failed or encountered a read problem on one of its late disks; the exact count and disk are not certain. The lesson was clear: a late removable-media failure could interrupt a long installation.

03CONNECT

Connecting to the world

MEMORY An early 56k modem and dial-up providers turned an offline computer into a connected one. ICQ—number 166847991—made messaging immediate. DSL 1000 and improvised cabling later made the connection available where it was needed.

OFFLINE PC→DIAL-UP→ICQ→DSL

FIELD NOTE

Data outlives the machine

A discarded neighbouring PC retained private and business data. It was an early practical privacy lesson: DELETE ≠ SECURE ERASURE and DISCARDING HARDWARE ≠ DISCARDING THE DATA. Old storage can retain recoverable information unless it is properly erased.

04OPEN / MODIFY

Build it yourself

MEMORY Discarded hardware and second-hand components became Frankenstein systems assembled from what worked. Machines were opened to understand or modify them; at least one operated in an unconventional open configuration, with a motherboard mounted on a wall.

05BREAK / UNDERSTAND

Breaking Linux

MEMORY Debian, Slackware, SUSE and Linux Mint were environments for trial and error—not a neat distribution timeline. Bootloaders, partitions, X, sound and graphics sometimes broke; repairing them changed the question from “How do I use this?” to “Why does this work?”

RECONSTRUCTION

06REPURPOSE

Make it do something else

MEMORY Linux on an old Premiere decoder / receiver-type device, hardware and audio modifications, and other experiments asked a different question: not what a machine was designed to do, but what else it could be made to do. The same approach continues in a Windows 98 retro PC, local ICQ-compatible infrastructure, and modern Linux systems communicating with the retro environment.

REPURPOSE → CREATE
