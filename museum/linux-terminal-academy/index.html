TERMINAL FIRST STEPS

FUTURE: pwd whoami uname date ls cd clear help

WHERE AM I? · WHO AM I? · WHAT FILES ARE HERE?

02PLANNED

FILESYSTEM EXPLORER

Learn relative and absolute paths in a filesystem tree rooted at /, rather than primarily around drive letters.

/
├── bin
├── etc
├── home
│   └── museum
├── tmp
└── var

Linux can still mount multiple devices and filesystems into that tree. A future cd /var/log will highlight the current location.

03PLANNED

FILES & DIRECTORIES LAB

Future commands such as mkdir, touch, cp, mv, rm, cat, less, head and tail will modify real fictional virtual filesystem state.

CREATE projects/ · CREATE notes.txt · COPY · RENAME · DELETE

GOOD. YOU DELETED IT. NOW RECOVER IT.

Mistakes are allowed; experimentation is the point.

04PLANNED

PERMISSIONS & USERS LAB

Explore users, groups, ownership and rwx permissions with whoami, id, users, groups and ls -l.

A fictional script cannot run. Inspect why, then make the smallest appropriate fix with the chmod concept.

NOT “JUST PUT SUDO IN FRONT.” UNDERSTAND THE DENIAL FIRST.

Root and sudo remain fictional; there is no real privilege escalation.

05PLANNED

PROCESS CONTROL ROOM

See the difference between a program on disk and a running process. Explore PIDs, ps, a top-like view, foreground/background work, signals and the kill concept.

PID   COMMAND         CPU
101   museum-shell     1%
205   archive-index    3%
319   runaway-job     99%

SYSTEM SLOW → FIND IT → INSPECT IT → STOP IT

No browser or operating-system processes are accessed.

06PLANNED

PIPES & SHELL POWER

cat system.log | grep ERROR | wc -l

system.log↓cat↓ text streamgrep ERROR↓ matching lineswc -l↓17

The output of one program can become the input of another. This composability is one of the shell’s major strengths.

Future concepts: |, >, >>, wildcards, grep, find, sort and wc. Nothing executes on a real machine.

07PLANNED

SYSTEM ADMIN CRASH LAB

MUSEUM WEB SERVICE — STATUS: FAILED

Trace a fictional failure: service status → logs → configuration → fix → restart → ACTIVE (RUNNING).

Future concepts include services, logs, configuration, package-management ideas, and systemctl- and journalctl-style diagnostics.

READ · DIAGNOSE · UNDERSTAND · FIX

No real services or system commands are involved.

08PLANNED

BREAK IT & RECOVER

The eventual integrated challenge: a deleted configuration, wrong permission, runaway process, broken service, full virtual filesystem, bad environment variable, missing file or symbolic-link mistake.

SYSTEM DEGRADED. FIND OUT WHY.

There will be no immediate step-by-step answer—only the concepts learned in earlier labs and a reversible environment.

RESET VIRTUAL MACHINE

YOU BROKE IT. YOU UNDERSTOOD WHY. YOU FIXED IT. THAT IS HOW YOU LEARN LINUX.

LINUX IS NOT ONE DESKTOP

LINUX SYSTEM
├── Kernel
├── Userspace
├── Shell
├── Display system / Wayland or X
└── Desktop environment / compositor / window manager

Linux is not synonymous with Ubuntu, GNOME, KDE or the terminal. Desktop environments, compositors and window managers are different layers and options; GNOME, KDE Plasma and sway are small examples, not a comparison chart.

FUTURE SHARED VIRTUAL-SYSTEM ARCHITECTURE

All eight labs are planned around one consistent browser-side fictional Linux state model, not eight unrelated fake terminals.

A future sequence like mkdir test, cd test, touch hello.txt, mv hello.txt ../ will consistently change fictional browser-side state. Later lessons can reuse current directory, files, users/groups, permissions, processes, services, logs and environment variables. Optional progress or virtual-machine persistence is deferred; RESET VIRTUAL MACHINE will always remain available.

SAFETY & TRANSPARENCY

Commands may resemble Unix/Linux commands for educational purposes, but their future behavior will exist only inside an original fictional browser-side virtual environment.

  • No real shell or Linux commands.
  • No access to your files, processes, services or operating system.
  • No real sudo/root access, SSH, external network access or package installation.
  • No modification of your computer.
