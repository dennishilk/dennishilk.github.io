05 / UNDERSTAND & INSPECT
Understand the work
Compression and encryption
Compression saves space. Encryption controls access. A ZIP file can use both, and a visible filename does not mean its contents are readable.
Why AES searches cost more
ZipCrypto is an older, weak encryption scheme with a cheap password-header check. A header match alone is never accepted: the lab decrypts and checks CRC-32. ZIP-AES uses PBKDF2-HMAC-SHA-1 with 1,000 rounds to derive keys, then verifies the authentication tag. Key stretching makes every guess more expensive.
Candidate order and password strength
Dictionary searches benefit from familiar words, case changes, leetspeak and predictable years. Longer random passwords can create an impractical search space. An exhausted selected search only rules out those candidates; it does not prove a password is unbreakable.
Supported formats and honest limits
This release supports single-volume ZIP, ZipCrypto and WinZip AES AE-1/AE-2, Stored and Deflate compression, data descriptors, and small ZIP64 archives within the limits. An archive must share one password across its encrypted files. Unsupported: RAR4/RAR5, 7Z, PDF (including opening-password recovery and decrypted export), split archives, self-extracting archives, other compression methods, PKWARE strong encryption, and archives containing only empty ZipCrypto files. RAR, 7Z and PDF require their own derivation, validation and export engines. Their costs are never estimated using this ZIP verifier. Search candidates are ASCII only; legacy non-UTF-8 password encodings are unsupported. PDF owner/printing restrictions are distinct from a document-opening password.
Privacy and resource limits
Maximum input 32 MiB; 256 entries; 16 MiB per extracted file; 32 MiB total output; compression ratio at most 200:1. Unsafe paths, duplicate output names and symlinks are rejected. Archives inside an archive are downloaded as ordinary files and never recursively opened or executed. Reset terminates Workers and releases download URLs. JavaScript garbage collection cannot guarantee secure memory erasure. Nothing is saved to localStorage, IndexedDB or a service worker. Offline recovery works once the page and shared dictionary assets are loaded.
