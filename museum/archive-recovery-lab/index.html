    04 / UNDERSTAND & INSPECT
    Understand the work
    Compression and encryption
    Compression saves space. Encryption controls access. A ZIP file can use both, and a visible filename does not mean its contents are readable.
    Why AES searches cost more
    ZipCrypto is an older, weak encryption scheme with a cheap password-header check. A header match alone is never accepted: the lab decrypts and checks CRC-32. ZIP-AES uses PBKDF2-HMAC-SHA-1 with 1,000 rounds to derive keys, then verifies the authentication tag. Key stretching makes every guess more expensive.
    Candidate order and password strength
    Dictionary searches benefit from familiar words, case changes, leetspeak and predictable years. Longer random passwords can create an impractical search space. An exhausted selected search only rules out those candidates; it does not prove a password is unbreakable.
    Supported formats and honest limits
    This release supports ZIP ZipCrypto, WinZip AES-128/192/256 AE-1/AE-2 (Stored/Deflate), tested header-encrypted RAR4/RAR5, 7Z AES-256 with encrypted headers and LZMA2, and PDF opening-password Security Handler revisions R2/RC4-40, R3/RC4-128, R4/AES-128 and R6/AES-256. Matching passwords are independently confirmed against actual content before downloads. RAR/7Z support covers verified variants only; multi-volume, unusual codecs, unverified PDF revisions and unsupported encryption may be rejected. ZIP input ≤32 MiB; other input ≤8 MiB. A search does not guarantee that a long random password can be recovered. PDF owner-only permissions are not treated as opening-password recovery. Candidate enumeration is currently ASCII-based.
    Privacy and resource limits
    Input: ZIP at most 32 MiB; RAR/7Z/PDF at most 8 MiB; 256 entries; 16 MiB per extracted file; 32 MiB total output; compression ratio at most 200:1. Unsafe paths, duplicate output names and symlinks are rejected. Archives inside an archive are downloaded as ordinary files and never recursively opened or executed. Reset terminates Workers and releases download URLs. JavaScript garbage collection cannot guarantee secure memory erasure. Nothing is saved to localStorage, IndexedDB or a service worker. Offline recovery works once the page and shared dictionary assets are loaded.
