Overview & identity

Mass-storage class 08 alone cannot distinguish Bulk-Only from UAS. For this generic profile, confirm interface subclass and protocol as well as the observed usb-storage binding.

This is an explicit class, transport or driver-context profile. It is not an exact numeric product match.

A numeric match establishes a candidate family within the reviewed evidence. Marketing names, board variants, subsystem conditions and successful operation remain separate questions.

Driver & binding

usb_storage registers a USB interface driver and hands storage to the SCSI/block layers. A bridge can expose an ATA, NVMe or flash device behind the same USB transport; those are different identities.

Read-only diagnostics

Run one displayed command at a time. Replace uppercase placeholders with the affected device, interface or module from your own output. Commands are never executed here. Read-only output can still contain private identifiers.

Inspect interfaces and negotiated speed

lsusb -t

This read-only usbutils query normally needs no sudo. Driver belongs to the displayed interface, while speed is the negotiated connection. Other interfaces of the same physical device may use other drivers.

Associate transport with block devices

lsblk -o NAME,TYPE,TRAN,MODEL,SIZE

This read-only util-linux query normally needs no sudo. TRAN=usb identifies the outer transport, while MODEL is a reported label and may describe a bridge or device rather than verified silicon.

Limitations & related issues

A transport binding does not identify the bridge chipset or establish disk health. Do not turn UAS off based only on a generic USB storage label; that would be a configuration change requiring separate evidence.
