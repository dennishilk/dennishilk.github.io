Overview & identity

Class 08 is only secondary context; the UAS path examines SCSI subclass, interface alternatives and protocol. A product advertising USB 3 is not automatically observed to use UAS.

This is an explicit class, transport or driver-context profile. It is not an exact numeric product match.

A numeric match establishes a candidate family within the reviewed evidence. Marketing names, board variants, subsystem conditions and successful operation remain separate questions.

Driver & binding

The uas driver has class matches for relevant storage interfaces and checks whether the UAS alternative can be used. Actual lsusb -t binding tells whether uas or usb-storage won probing on this boot.

Read-only diagnostics

Run one displayed command at a time. Replace uppercase placeholders with the affected device, interface or module from your own output. Commands are never executed here. Read-only output can still contain private identifiers.

Inspect interfaces and negotiated speed

lsusb -t

This read-only usbutils query normally needs no sudo. Driver belongs to the displayed interface, while speed is the negotiated connection. Other interfaces of the same physical device may use other drivers.

Read this boot’s storage and USB messages

journalctl -k -b --no-pager

This reads kernel messages without changing the driver. Access depends on journal permissions; use sudo only if the local policy denies the read. Correlate reset timestamps with the same port and storage target.

Limitations & related issues

Resets can involve the cable, power, bridge firmware, host controller or media. This profile neither identifies an exact bridge nor declares every UAS device affected by a quirk.
