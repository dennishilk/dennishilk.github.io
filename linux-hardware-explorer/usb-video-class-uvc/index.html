USB Video Class camera interfaces

UVC describes camera control and streaming interfaces, separate from any microphone in the same webcam.

Overview & identity

Video interface class 0e is a family hint. The checked generic table is narrower: video-control subclass 1 with defined UVC protocols. A numeric camera model is not established from the class alone.

This is an explicit class, transport or driver-context profile. It is not an exact numeric product match.

A numeric match establishes a candidate family within the reviewed evidence. Marketing names, board variants, subsystem conditions and successful operation remain separate questions.

Driver & binding

uvcvideo handles the video function and exposes V4L2 devices. A composite webcam may also have snd_usb_audio or HID interfaces; one interface binding cannot represent the complete webcam.

Read-only diagnostics

Run one displayed command at a time. Replace uppercase placeholders with the affected device, interface or module from your own output. Commands are never executed here. Read-only output can still contain private identifiers.

Inspect interfaces and negotiated speed

lsusb -t

This read-only usbutils query normally needs no sudo. Driver belongs to the displayed interface, while speed is the negotiated connection. Other interfaces of the same physical device may use other drivers.

Inspect exposed V4L2 device links

ls -l /sys/class/video4linux/

Read device symlinks without sudo. Follow the paths to distinguish capture and metadata nodes from the same camera; this does not start a recording.

Limitations & related issues

The existence of a video node does not prove the desired resolution, frame rate, access permission or application selection. Vendor-specific modes and firmware loading are outside this generic class match.

These guides are linked for relevant observations, not as known defects of every device in this family.
