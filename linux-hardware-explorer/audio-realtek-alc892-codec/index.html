Overview & identity

HDA codec ID 0x10ec0892 appears in the checked ALC662-family table as ALC892. It is not a PCI pair: entering 10ec:0892 as a PCI device match would confuse the codec with the controller.

This is an explicit class, transport or driver-context profile. It is not an exact numeric product match.

A numeric match establishes a candidate family within the reviewed evidence. Marketing names, board variants, subsystem conditions and successful operation remain separate questions.

Driver & binding

This source snapshot builds snd_hda_codec_alc662 for this codec family, with shared Realtek code. Installed kernels can organize codec modules differently. Inspect the codec proc data and the running modules rather than using the controller vendor to guess the codec.

Read-only diagnostics

Run one displayed command at a time. Replace uppercase placeholders with the affected device, interface or module from your own output. Commands are never executed here. Read-only output can still contain private identifiers.

Read HDA codec descriptions

cat /proc/asound/card*/codec*

Read available HDA codec proc files without changing mixer controls. Normally no sudo is required. Codec vendor/subsystem IDs are HDA identities and must not be interpreted as the PCI controller VID/DID; unavailable proc entries leave this layer unknown.

List playback PCM endpoints

aplay -l

This read-only alsa-utils listing normally needs no sudo and does not play audio. Compare card/device numbers with the card list; a PCM endpoint is separate from a PipeWire profile and mixer state.

Limitations & related issues

Subsystem IDs, board wiring and codec renaming affect the final jack layout. A module-family match is contextual evidence, not confirmation that this machine has ALC892 or that every output works.
